# Sri Karaoke 🎤

แอปคาราโอเกะที่ดึงเพลงจากยูทูบมาแสดงบนจอทีวี พร้อมให้เพื่อน ๆ สแกน QR Code เพื่อค้นหาและเพิ่มเพลงเข้าคิวจากมือถือของตัวเอง

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` + `app.js` | หน้าจอหลัก แสดงผลบนทีวี/จอใหญ่ — เล่นวิดีโอ, แสดงคิว, สร้าง QR Code |
| `remote.html` + `remote.js` | หน้ารีโมทสำหรับมือถือ — ค้นหาเพลง, จัดการคิว |
| `manifest.json` / `manifest-remote.json` | ไฟล์ตั้งค่า PWA ของแต่ละหน้า |
| `sw.js` | Service Worker สำหรับติดตั้งเป็นแอปและใช้งานแบบออฟไลน์บางส่วน |
| `icons/` | ไอคอนแอป |

## วิธีการทำงาน

- จอหลักและมือถือแต่ละเครื่องเชื่อมต่อกันแบบ **peer-to-peer (WebRTC)** ผ่านไลบรารี PeerJS โดยไม่ต้องมีเซิร์ฟเวอร์ของตัวเอง
- เมื่อเปิด `index.html` บนทีวี ระบบจะสุ่ม **รหัสห้อง** และสร้าง QR Code ที่มีลิงก์ไปยัง `remote.html?room=...`
- เพื่อนสแกน QR ด้วยกล้องมือถือ → เบราว์เซอร์เปิด `remote.html` → เชื่อมต่อกับจอหลักอัตโนมัติ
- การเพิ่ม/ลบ/ข้าม/แทรกเพลง จะซิงก์ไปยังทุกอุปกรณ์ที่เชื่อมต่ออยู่แบบเรียลไทม์

⚠️ **สำคัญ:** เพราะใช้ QR Code ที่เป็นลิงก์เว็บ ต้อง **โฮสต์ไฟล์ทั้งหมดไว้บนเว็บเซิร์ฟเวอร์** (ไม่ใช่เปิดไฟล์ตรง ๆ แบบ `file://`) มือถือถึงจะเปิดลิงก์และสแกน QR ได้ วิธีที่ง่ายที่สุด:

### วิธีที่ 1 — โฮสต์ฟรีบนอินเทอร์เน็ต (แนะนำ)
อัปโหลดโฟลเดอร์นี้ขึ้น GitHub Pages, Netlify, Vercel หรือ Cloudflare Pages (ลากไฟล์วางก็ใช้ได้ทันที) แล้วเปิด `index.html` ผ่าน URL ที่ได้บนจอทีวี/คอมที่ต่อจอทีวี

### วิธีที่ 2 — รันในวงแลนบ้าน (ไม่ต้องต่อเน็ตนอกบ้าน)
บนเครื่องที่ต่อกับจอทีวี เปิด Terminal ในโฟลเดอร์นี้แล้วรัน:
```bash
python3 -m http.server 8000
```
จากนั้นเปิดเบราว์เซอร์บนทีวี/กล่องแอนดรอยไปที่ `http://<IP เครื่องนี้ในวงแลน>:8000/index.html`
มือถือที่ต่อ Wi-Fi วงเดียวกันจะสแกน QR แล้วเข้าถึง `remote.html` ได้ปกติ (ต้องเชื่อมต่ออินเทอร์เน็ตด้วย เพราะ PeerJS และ YouTube ต้องใช้เน็ต)

⚠️ วิธีนี้เป็น HTTP ธรรมดา (ไม่ใช่ HTTPS) แอปจะแสดงแบนเนอร์เตือนและการเชื่อมต่อรีโมทอาจไม่เสถียรเท่าที่ควร ใช้ได้สำหรับทดสอบ/งานเล็กๆ ในบ้าน แต่ถ้าจะใช้งานจริงจัง แนะนำวิธีที่ 1 (โฮสต์บน HTTPS ฟรี) หรือใช้เครื่องมืออย่าง `ngrok`/`cloudflared` เปิดทันเนล HTTPS ชั่วคราวมาที่เครื่องในบ้านแทน

## การติดตั้งเป็นแอป (PWA)

- **บนทีวี/กล่องแอนดรอย:** เปิด `index.html` ด้วย Chrome แล้วเลือก "ติดตั้งแอป" หรือ "Add to Home screen"
- **บนมือถือ:** เปิดลิงก์รีโมท (จากการสแกน QR) แล้วเลือก "เพิ่มลงหน้าจอหลัก" — ครั้งต่อไปเปิดจากไอคอนแอปได้เลย

## การค้นหาเพลง

- **วางลิงก์ YouTube โดยตรง** ในช่องค้นหาบนรีโมท ใช้งานได้ทันทีโดยไม่ต้องตั้งค่าอะไร
- **ค้นหาด้วยคำ** (เช่น พิมพ์ชื่อเพลง) ต้องมี YouTube Data API Key ฟรี:
  1. ไปที่ [Google Cloud Console](https://console.cloud.google.com/)
  2. สร้างโปรเจกต์ใหม่ → เปิดใช้งาน "YouTube Data API v3"
  3. สร้าง API Key แล้วคัดลอกมาใส่ในแท็บ "ตั้งค่า" บนหน้ารีโมท

ถ้าลบข้อความในช่องค้นหาจนว่างเปล่า รายการผลการค้นหาเดิมจะหายไปด้วยอัตโนมัติ (ทั้งจอหลักและรีโมท) ไม่ค้างอยู่ให้สับสนว่าเป็นผลจากคำค้นไหน

## ฟีเจอร์ที่รองรับ

- ✅ เล่นวิดีโอจาก YouTube ผ่าน YouTube IFrame Player
- ✅ **เล่นเพลงถัดไปในคิวอัตโนมัติเมื่อเพลงจบ** และ **ลบเพลงที่เล่นจบ/ถูกข้ามออกจากคิวให้อัตโนมัติ**
- ✅ **แสดงชื่อเพลงถัดไปล่วงหน้า** ที่มุมบนของจอขณะเพลงกำลังเล่น หรือแจ้งเตือน "ไม่มีเพลงในคิว...กรุณาเลือกเพลง" ถ้าไม่มีเพลงต่อคิว
- ✅ ค้นหาเพลงได้จาก **จอหลักโดยตรง** — ใช้งานแบบจอเดียวได้เต็มรูปแบบโดยไม่ต้องมีใครสแกน QR ก็ค้นหาและกด "เล่นเลย"/"+ คิว" ได้
- ✅ ผลการค้นหาแสดงภาพตัวอย่างย่อ (thumbnail) พร้อมชื่อเพลง/ช่อง ทั้งบนจอหลักและรีโมท
- ✅ ระบบคิวเพลง: เพิ่ม, ลบ, แทรกเล่นถัดไป, **จัดเรียงลำดับคิวได้** (ลากวางด้วยเมาส์ หรือกดปุ่ม ▲▼ — ใช้งานบนจอหลัก)
- ✅ จัดการเพลย์ลิสต์: บันทึกคิวปัจจุบันเป็นเพลย์ลิสต์ และโหลดกลับมาใช้ภายหลัง (จอหลัก)
- ✅ ปรับจังหวะ (Tempo) ของเพลงที่กำลังเล่นได้ **ทั้งจากจอหลักและรีโมท**
- ✅ สแกน QR Code เพื่อควบคุมผ่านมือถือหลายเครื่องพร้อมกัน
- ✅ **รีโมทแอดมิน แยก QR จากรีโมทผู้ใช้ทั่วไป** — แจกสิทธิ์ควบคุมเต็มรูปแบบให้เฉพาะคนที่ไว้ใจ
- ✅ **ล็อกห้องด้วยรหัส PIN** (ทางเลือก) กันคนแปลกหน้าที่ไม่มีลิงก์เข้ามาคุมคิว
- ✅ **API Key ค้นหาเพลงมาให้พร้อมใช้งานทันที** (เปลี่ยนเป็นของตัวเองได้ตลอดเวลา)
- ✅ **ซ่อน/แสดงคิวเพลงบนจอหลักได้** เพื่อโฟกัสที่วิดีโอเต็มจอ
- ✅ **โหมดเต็มจอของแอป** (ไม่ใช่แค่ของ YouTube) พร้อม**ซ่อน/แสดงเมนูด้วยการแตะจอ**
- ✅ **ประวัติเพลงที่เล่นไปแล้ว** พร้อมเหตุผลที่เปลี่ยนเพลง เวลาที่ผ่านมา และปุ่มเพิ่มกลับเข้าคิว
- ✅ **แสดงคอร์ดกีตาร์แบบเรียลไทม์** ที่มุมบนจอ (คอร์ดที่เตรียมไว้เอง ผูกกับเพลง เล่นซ้ำครั้งไหนก็ขึ้นเอง)
- ✅ **สำรอง/กู้คืนข้อมูลทั้งหมด** (เพลย์ลิสต์ + ประวัติ + คอร์ด) เป็นไฟล์ .json เดียว
- ✅ รองรับภาษาไทยเต็มรูปแบบ (ฟอนต์ Kanit / Sarabun)
- ✅ ติดตั้งเป็นแอป (PWA) ได้ทั้งจอทีวีและมือถือ
- ✅ รองรับหน้าจอแนวตั้งและแนวนอน (responsive)
- ✅ นำทางด้วยรีโมททีวี/กล่องแอนดรอย — ปุ่มทุกปุ่มโฟกัสได้ด้วย D-pad, รองรับปุ่ม Back/ปุ่มสื่อ (เล่น/หยุด/ข้าม)

## สิทธิ์การควบคุม (จอหลัก vs รีโมทแอดมิน vs รีโมทผู้ใช้ทั่วไป)

เพื่อไม่ให้เพลงที่กำลังเล่นถูกสลับ/ข้ามโดยไม่ได้ตั้งใจจากมือถือหลายเครื่องพร้อมกัน จึงแบ่งสิทธิ์เป็น 3 ระดับ:

| การทำงาน | จอหลัก | 👑 รีโมทแอดมิน | 👤 รีโมทผู้ใช้ทั่วไป |
|---|:---:|:---:|:---:|
| ค้นหา/เพิ่มเพลงเข้าคิว | ✅ | ✅ | ✅ |
| ลบ/ยกเลิกเพลงออกจากคิว | ✅ | ✅ | ✅ |
| ปรับจังหวะ (Tempo) | ✅ | ✅ | ✅ |
| ปรับระดับเสียง / ปิดเสียง | ✅ | ✅ | ✅ |
| เล่น/หยุด, ข้าม, ก่อนหน้า | ✅ | ✅ | ❌ (แสดงผลอย่างเดียว) |
| จัดเรียงลำดับคิว / แทรกเล่นถัดไป | ✅ | ✅ | ❌ (ดูคิวได้อย่างเดียว) |
| เปิดเพลย์ลิสต์ | ✅ | ✅ | ❌ (ดูรายชื่อได้อย่างเดียว) |
| บันทึกเพลย์ลิสต์ใหม่ | ✅ | ❌ | ❌ |
| เปลี่ยน/ปิดเปิดรหัส PIN และรหัสแอดมิน | ✅ | ❌ | ❌ |

รายละเอียดวิธีแจก QR แอดมิน/ผู้ใช้ทั่วไปอยู่ในหัวข้อ "รีโมทแอดมิน vs รีโมทผู้ใช้ทั่วไป" ด้านล่าง

## คิวคนร้อง (แบ่งคิวเท่าเทียม)

ปกติเพลงจะเข้าคิวตามลำดับที่มีคนเพิ่ม ถ้าคนใดคนหนึ่งเพิ่มเพลงรัวๆ หลายเพลงติดกัน คนอื่นจะต้องรอนาน กดปุ่ม **"👥 คิวคนร้อง: ปิด"** ที่มุมขวาของแผงคิวเพลง (จอหลัก) เพื่อเปิดโหมดนี้ — ระบบจะจัดเรียงเพลงที่ยังไม่ได้เล่นใหม่แบบสลับคิวกันในแต่ละคน (คนละเพลงต่อรอบ) โดยไม่แตะเพลงที่กำลังเล่นอยู่ ค่าเริ่มต้นคือ **ปิด** จึงไม่กระทบพฤติกรรมเดิมถ้าไม่ได้เปิดใช้งาน

## เล่นเพลงถัดไปอัตโนมัติ + ลบเพลงที่เล่นจบออกจากคิว

ตอนนี้เมื่อเพลงที่กำลังเล่นจบลง (หรือถูกกดข้าม หรือเล่นไม่ได้) ระบบจะ:
1. **ลบเพลงนั้นออกจากคิวโดยอัตโนมัติ** (เพลงที่เล่น/ข้ามไปแล้วจะไม่ค้างอยู่ในรายการคิวอีกต่อไป — ยังดูย้อนหลังได้เสมอผ่าน "🕘 ประวัติ")
2. **เล่นเพลงถัดไปในคิวต่อทันที** ถ้ายังมีเพลงเหลืออยู่
3. ถ้าไม่มีเพลงเหลือแล้ว ระบบจะหยุดเล่นและกลับไปที่หน้าจอว่าง (screensaver)

**มุมบนของจอ (ระหว่างที่มีเพลงเล่นอยู่)** จะแสดง **"▶ ถัดไป: [ชื่อเพลง]"** ให้เห็นล่วงหน้าตลอดเวลาที่เพลงปัจจุบันกำลังเล่น หรือถ้าไม่มีเพลงต่อคิวแล้ว จะขึ้นข้อความเตือน **"⚠️ ไม่มีเพลงในคิว...กรุณาเลือกเพลง"** แทน เพื่อให้คนคุมจอหลัก/เพื่อนๆ รู้ตัวก่อนเพลงจบและรีบเพิ่มเพลงใหม่ทัน

⚠️ **ผลข้างเคียงที่ควรทราบ:** เพราะเพลงที่เล่นจบจะถูกลบออกจากคิวทันที ปุ่ม **"⏮ ก่อนหน้า"** (ย้อนกลับไปเพลงก่อนหน้า) จะใช้งานไม่ได้อีกต่อไปในสถานการณ์ปกติ เนื่องจากเพลงก่อนหน้าไม่ได้อยู่ในคิวแล้ว (ต้องไปเปิดใหม่จากประวัติแทน) ส่วนการ **"เล่นเลย"** (แทรกเพลงเล่นด่วนแทรกกลางคิว) ยังทำงานตามปกติ — เพลงที่ถูกแทรกแซงจะไม่ถูกลบ แต่จะถูกเลื่อนไปรอเล่นทีหลังแทน ไม่ใช่หายไปเลย

## เพลงแนะนำ

หน้าค้นหาเพลงบนจอหลัก มีปุ่ม **"🎵 เพลงแนะนำ"** อยู่ข้างปุ่ม "ปิด" ด้านล่างของหน้าต่างค้นหา กดเพื่อเปิด/ปิดรายการชิปเพลงยอดนิยมที่แตะแล้วค้นหาได้ทันทีโดยไม่ต้องพิมพ์ (ค่าเริ่มต้นซ่อนไว้ ไม่โชว์ค้างอยู่ตลอดเวลาเหมือนก่อนหน้านี้) แก้ไขรายการเพลงแนะนำได้เองที่ตัวแปร `SUGGESTED_SONGS` ในไฟล์ `app.js` เพื่อปรับให้เหมาะกับกลุ่มคนในงานของคุณ

## ปรับระดับเสียง (จอหลัก + รีโมท)

นอกจากจังหวะ (Tempo) แล้ว ตอนนี้ปรับ **ระดับเสียง** และ **ปิด/เปิดเสียง (mute)** ได้ทั้งจากจอหลักและรีโมททุกคน (เหมือนกับ Tempo) เผื่อใครนั่งไกลทีวีอยากปรับเสียงจากมือถือตัวเองได้เลยโดยไม่ต้องเดินไปที่จอหลัก

## สำรอง/กู้คืนข้อมูลทั้งหมด (เพลย์ลิสต์ + ประวัติ + คอร์ด)

ในหน้าต่างเพลย์ลิสต์ (จอหลัก) มีปุ่ม:
- **"⬇️ สำรองข้อมูลทั้งหมด (.json)"** — ดาวน์โหลดไฟล์เดียวที่รวม **เพลย์ลิสต์ + ประวัติเพลง + คอร์ดเพลง** ทั้งหมดที่บันทึกไว้ ใช้สำรองข้อมูลหรือย้ายไปใช้กับเบราว์เซอร์/อุปกรณ์อื่นได้
- **"⬆️ กู้คืนข้อมูล (.json)"** — เลือกไฟล์ที่เคยส่งออกไว้ (หรือไฟล์ที่แชร์กันมา) เพื่อนำเข้ากลับมา โดย:
  - **เพลย์ลิสต์**: ถ้าชื่อซ้ำกับที่มีอยู่แล้ว ระบบจะเติม "(นำเข้า)" ต่อท้ายให้อัตโนมัติเพื่อไม่ให้ข้อมูลเดิมหาย
  - **ประวัติเพลง**: นำเข้าแบบผสานกับประวัติเดิม (ไม่ลบของเก่า) เรียงตามเวลาล่าสุดให้ใหม่
  - **คอร์ดเพลง**: นำเข้าเฉพาะเพลงที่ **ยังไม่เคยมีคอร์ดบันทึกไว้ในเครื่องนี้** เท่านั้น เพื่อไม่ให้ไปทับคอร์ดที่แก้ไว้แล้ว (ถ้าเพลงไหนมีอยู่แล้วจะข้ามไปและแจ้งจำนวนที่ข้ามให้ทราบ)
  - รองรับไฟล์เพลย์ลิสต์รุ่นเก่า (ที่ส่งออกก่อนอัปเดตนี้) ด้วยเช่นกัน

## คอร์ดเพลงแบบเรียลไทม์ (จอหลัก)

แสดงคอร์ดกีตาร์ของเพลงที่กำลังเล่น เป็นแถบอยู่ด้านบนจอ (ใต้เมนู เหนือวิดีโอ) — คอร์ดปัจจุบันตัวใหญ่เด่น พร้อมคอร์ดถัดไป 2-3 ตัวข้างๆ ให้เตรียมเปลี่ยนคอร์ดทัน

**⚠️ ข้อจำกัดที่ต้องเข้าใจก่อนใช้:** ระบบนี้ **ไม่ได้ "แกะคอร์ดจากเสียงเพลงอัตโนมัติ"** เพราะวิดีโอมาจาก YouTube iframe ซึ่งเป็นคนละ origin กับเว็บเรา เบราว์เซอร์บล็อกไม่ให้เว็บเราเข้าถึงสัญญาณเสียงดิบของ iframe ได้เลย (เหตุผลเดียวกับที่ปรับ "คีย์เสียง" ไม่ได้) — คอร์ดที่แสดงเป็น **คอร์ดที่แอดมินพิมพ์เตรียมไว้เองล่วงหน้า** ผูกกับ videoId ของเพลงนั้น

### วิธีเพิ่มคอร์ด

1. เล่นเพลงที่ต้องการเพิ่มคอร์ด (หรือเล่นจากคิว/ประวัติ/เพลย์ลิสต์)
2. กดปุ่ม **"🎸 คอร์ด"** ที่ header
3. หน้าต่างจะเปิดขึ้นพร้อมคำแนะนำรูปแบบทั้ง 2 โหมดในตัว เลือกโหมดที่ต้องการ:

   **โหมดง่าย** — พิมพ์คอร์ดเรียงลำดับ คั่นด้วยช่องว่าง เช่น `C G Am F C G F G` พร้อมกำหนด "วินาทีต่อคอร์ด" (ค่าเริ่มต้น 4 วินาที) ระบบจะแบ่งเวลาให้เท่าๆ กันเอง — เร็ว ใช้เวลาไม่ถึงนาที แต่จังหวะอาจไม่ตรงเป๊ะกับเพลงจริง

   **โหมดละเอียด** — พิมพ์เวลา (นาที:วินาที) ตามด้วยคอร์ด บรรทัดละ 1 คอร์ด เช่น:
   ```
   0:00 C
   0:04 G
   0:08 Am
   0:12 F
   ```
   ต้องนั่งฟังเพลงแล้วจดเวลาที่คอร์ดเปลี่ยนเอง ใช้เวลานานกว่าแต่คอร์ดจะเปลี่ยนตรงจังหวะเพลงจริง

4. กด **"บันทึก"** — คอร์ดจะขึ้นแถบด้านบนทันที และเลื่อนตามเวลาเพลงเล่นอัตโนมัติ
5. ครั้งต่อไปที่เพลงเดียวกัน (videoId เดียวกัน) ถูกเล่น คอร์ดที่เคยบันทึกจะขึ้นเองโดยไม่ต้องพิมพ์ใหม่

### คลังคอร์ด

ด้านล่างของหน้าต่าง "🎸 คอร์ด" มีรายชื่อเพลงที่มีคอร์ดบันทึกไว้ทั้งหมด กด **"แก้ไข"** ที่รายการใดก็ได้เพื่อแก้ไขคอร์ดของเพลงนั้น (ใช้ได้แม้เพลงนั้นไม่ได้กำลังเล่นอยู่) หรือกด **"ลบคอร์ดเพลงนี้"** ในฟอร์มเพื่อลบคอร์ดของเพลงที่กำลังแก้ไขอยู่

### หมายเหตุเพิ่มเติม

- ถ้าเพลงที่กำลังเล่น **ยังไม่มีคอร์ดบันทึกไว้** แถบคอร์ดจะไม่แสดงเลย ไม่ไปกวนพื้นที่จอเปล่าๆ
- กรอ/ข้ามเวลาในวิดีโอ (seek) ได้ตามปกติ คอร์ดจะกระโดดตามเวลาที่ถูกต้องให้เองอัตโนมัติ (คำนวณจากเวลาจริงของวิดีโอทุกครั้ง ไม่ใช่แค่นับเวลาเดินไปเรื่อยๆ)
- คอร์ดถูกเก็บไว้ใน `localStorage` ของจอหลักเท่านั้น (เหมือนเพลย์ลิสต์/ประวัติ) และรวมอยู่ในระบบสำรอง/กู้คืนข้อมูลด้านบนแล้ว
- แสดงเฉพาะจอหลัก ไม่ส่งไปที่รีโมท

## ระบบให้คะแนนร้องเพลง + กระดานผู้นำ

เมื่อเพลงเล่นจบตามธรรมชาติ (ไม่นับกรณีกดข้ามกลางเพลง) ระบบจะ:
1. สุ่มคะแนนร้อง (60–100 คะแนน) พร้อมข้อความให้กำลังใจตามช่วงคะแนน (พยายามได้ดี! / เก่งมาก! / ยอดเยี่ยม! / เพอร์เฟค!)
2. แสดงป๊อปอัพคะแนนใหญ่ๆ กลางจอ ค้างไว้ประมาณ 3.5 วินาที
3. เปลี่ยนเป็นป๊อปอัพ **"🏆 5 อันดับคะแนนสูงสุด"** ค้างไว้อีกประมาณ 4.5 วินาที แล้วปิดตัวเองอัตโนมัติ (แตะที่ป๊อปอัพเพื่อปิดก่อนเวลาได้ทุกเมื่อ)

ป๊อปอัพนี้แสดงทั้งบนจอหลักและส่งไปแสดงบนมือถือของทุกคนที่เชื่อมต่ออยู่ด้วย (ทั้งรีโมทแอดมินและผู้ใช้ทั่วไป) เพื่อความสนุกร่วมกัน คะแนนทั้งหมดถูกเก็บสะสมไว้ใน localStorage ของจอหลัก เพื่อคำนวณอันดับ Top 5 ตลอดการเล่นในเซสชันนั้น

⚠️ หมายเหตุ: คะแนนเป็นการ **สุ่มเพื่อความสนุกเท่านั้น** ไม่ได้วิเคราะห์เสียงร้องจริง เนื่องจากการวิเคราะห์คุณภาพเสียงร้องจริงต้องเข้าถึงไมโครโฟนและประมวลผลเสียงแบบเรียลไทม์ ซึ่งเป็นการพัฒนาเพิ่มเติมนอกเหนือขอบเขตปัจจุบัน



ระบบนี้ปรับ **จังหวะ (Tempo/ความเร็ว)** ได้จริงผ่าน YouTube IFrame API แต่ **ไม่สามารถปรับคีย์เสียง (Pitch) แยกจากจังหวะได้** เนื่องจากข้อจำกัดของแพลตฟอร์ม — วิดีโอ YouTube ที่ฝังผ่าน iframe ไม่อนุญาตให้เว็บภายนอกเข้าถึงข้อมูลเสียงดิบเพื่อประมวลผลปรับคีย์ (เป็นการป้องกันเนื้อหาของ YouTube เอง) หากต้องการฟีเจอร์ปรับคีย์เสียงจริง จะต้องเปลี่ยนแหล่งเสียงจากไฟล์ YouTube ไปเป็นไฟล์เสียง/วิดีโอที่แอปควบคุมโดยตรง (เช่นไฟล์ที่อัปโหลดเอง) แล้วประมวลผลด้วย Web Audio API แทน ซึ่งเป็นการพัฒนาเพิ่มเติมนอกเหนือขอบเขตปัจจุบัน

## ความเสถียรที่ปรับปรุงล่าสุด

- **รหัสห้องไม่เปลี่ยนเมื่อรีเฟรชจอหลัก** — เก็บรหัสห้องไว้ใน session ของแท็บ ถ้าจอหลักหลุด/รีเฟรชกลางงาน QR เดิมยังใช้ต่อได้โดยไม่ต้องสแกนใหม่ (จนกว่าจะปิดแท็บ)
- **รีโมทเชื่อมต่อใหม่อัตโนมัติ** — ถ้า Wi-Fi มือถือหลุดชั่วคราว ระบบจะพยายามเชื่อมต่อกลับให้เองโดยไม่ต้องออกจากหน้าเว็บ (มีแบนเนอร์แจ้งสถานะระหว่างเชื่อมต่อใหม่)
- **แจ้งเตือนเมื่อเปิดผ่าน HTTP** — ทั้งจอหลักและรีโมทจะแสดงแบนเนอร์เตือนถ้าไม่ได้เปิดผ่าน HTTPS (หรือ localhost) เพราะ WebRTC ทำงานไม่เสถียรบน HTTP ธรรมดา
- **ข้ามเพลงอัตโนมัติเมื่อเล่นไม่ได้** — ถ้าวิดีโอถูกลบ/ปิดการฝัง/เล่นไม่ได้ ระบบจะแจ้งเตือนบนจอหลักแล้วข้ามไปเพลงถัดไปให้อัตโนมัติ แทนที่จะค้าง
- **ปุ่ม "เริ่มระบบ"** — ต้องกดปุ่มนี้ที่จอหลัก **1 ครั้งก่อนเริ่มงาน** เพื่อปลดล็อกการเล่นเสียงอัตโนมัติ เพราะเบราว์เซอร์จะบล็อกไม่ให้เล่นเสียงจากคำสั่งที่มาจากมือถือ (ไม่ใช่การคลิกโดยตรงบนจอหลัก) จนกว่าจะมีการคลิกบนจอหลักอย่างน้อยหนึ่งครั้ง หลังจากกดแล้วเพื่อนๆ เพิ่มเพลงจากมือถือได้ตามปกติตลอดงาน
- **เพิ่ม STUN server สำรองหลายตัว** — ช่วยให้การเชื่อมต่อรีโมทหาทางเชื่อมต่อกันข้ามเครือข่ายที่แตกต่างกันได้ดีขึ้น (ดูหัวข้อ "การเชื่อมต่อรีโมทหลุดๆ ติดๆ" ด้านล่างสำหรับรายละเอียดและวิธีแก้เพิ่มเติมถ้ายังเจอปัญหา)

## การเชื่อมต่อรีโมทหลุดๆ ติดๆ ไม่เสถียร

ถ้ายังเจอปัญหาเชื่อมต่อไม่เสถียรหลังอัปเดตเวอร์ชันนี้ (ซึ่งเพิ่ม STUN server สำรองให้แล้ว) สาเหตุที่เป็นไปได้และวิธีแก้เรียงตามความเป็นไปได้:

1. **ไม่ได้เปิดผ่าน HTTPS** — เป็นสาเหตุอันดับ 1 ที่พบบ่อยที่สุด WebRTC (ที่ใช้เชื่อมต่อรีโมท) ทำงานไม่เสถียรมากบน HTTP ธรรมดา ต้องเปิดผ่าน HTTPS จริง (เช่น GitHub Pages) หรือ `localhost` เท่านั้น — ดูหัวข้อ "แนะนำวิธีการนำโปรเจกต์อัปโหลดไปยัง GitHub Pages" ในบทสนทนาก่อนหน้า หรือแบนเนอร์เตือนสีเหลืองที่ขึ้นบนจอถ้ายังเปิดผ่าน HTTP อยู่
2. **เครือข่ายที่มี NAT/Firewall เข้มงวด** (Wi-Fi โรงแรม, Wi-Fi ออฟฟิศ, มือถือบางเครือข่าย) — STUN server ที่เพิ่มให้แล้วช่วยได้ระดับหนึ่ง แต่เครือข่ายที่เข้มงวดมากบางกรณีต้องมี **TURN server** (relay การเชื่อมต่อ) ถึงจะทะลุผ่านได้ ซึ่งเป็นบริการที่ต้องสมัครสมาชิก (มีแพ็กเกจฟรีจากผู้ให้บริการอย่าง metered.ca, Twilio, Xirsys) แล้วนำ URL/username/credential มาใส่ในไฟล์ `app.js` และ `remote.js` ที่ตัวแปร `ICE_CONFIG` — มีคอมเมนต์กำกับไว้ในโค้ดทั้งสองไฟล์แล้วว่าต้องเพิ่มบรรทัดแบบไหน (`{ urls: 'turn:YOUR_TURN_HOST:3478', username: 'YOUR_USERNAME', credential: 'YOUR_CREDENTIAL' }`)
3. **เปิดหน้ารีโมทค้างไว้หลายแท็บ/หลายเครื่องพร้อมกันมากเกินไป** — จอหลักต้อง broadcast สถานะให้ทุกการเชื่อมต่อพร้อมกัน ถ้ามือถือหลายสิบเครื่องเชื่อมพร้อมกันอาจทำให้จอหลัก (ถ้าเป็นมือถือ/กล่องแอนดรอยที่แรงไม่มาก) หน่วงได้ ลองทดสอบกับจำนวนเครื่องน้อยลงเพื่อดูว่าอาการดีขึ้นหรือไม่
4. **Broker กลางของ PeerJS (0.peerjs.com) เป็นบริการฟรีสาธารณะ** ไม่มี SLA รับประกันความเสถียร ถ้าอาการยังไม่ดีขึ้นหลังลองข้อ 1-3 แล้ว ทางเลือกสุดท้ายคือการรันเซิร์ฟเวอร์ PeerServer ของตัวเอง (`npm install peer` แล้วตั้งค่า custom host/port ใน `new Peer()`) ซึ่งเป็นการเปลี่ยนสถาปัตยกรรมที่ใหญ่ขึ้น — แจ้งมาได้ถ้าต้องการให้ช่วยตั้งค่าส่วนนี้เพิ่มเติม

## เรื่องโฆษณาก่อนเริ่มเพลง

**บล็อกโฆษณาที่ฝังมากับวิดีโอ YouTube จากภายในโค้ดของแอปนี้ไม่ได้ และไม่ควรทำครับ** ขออธิบายเหตุผลทางเทคนิค:

- วิดีโอเล่นผ่าน **YouTube IFrame Player API** อย่างเป็นทางการ ซึ่ง Google ไม่เปิดช่องให้เว็บภายนอกตรวจจับหรือข้ามโฆษณาได้เลย (ไม่มีคำสั่ง "ข้ามโฆษณา" ใน API)
- ตัว iframe ของ YouTube เป็นคนละ origin กับเว็บเรา เบราว์เซอร์บล็อกไม่ให้เว็บเราเข้าไปยุ่งกับเนื้อหาภายใน iframe ได้ (เพื่อความปลอดภัยของผู้ใช้ทุกเว็บไซต์ ไม่ใช่แค่เว็บนี้) จึงไม่มีทาง "คลิกข้ามโฆษณา" จากโค้ดของเราได้จริงๆ
- การพยายามหาวิธีเลี่ยง/แฮ็กรอบข้อจำกัดนี้ อาจผิดข้อกำหนดการใช้งาน (Terms of Service) ของ YouTube สำหรับ IFrame API ซึ่งเสี่ยงทำให้โดเมนที่ใช้ฝังวิดีโอถูกจำกัดสิทธิ์การเข้าถึงได้

**วิธีที่ใช้ได้จริงและถูกต้องตามนโยบาย:**
1. **ติดตั้งส่วนขยายบล็อกโฆษณา** (เช่น uBlock Origin, AdGuard) บนเบราว์เซอร์ของอุปกรณ์ที่ใช้เป็นจอหลัก — บล็อกได้ที่ระดับเครือข่าย/เบราว์เซอร์ก่อนโฆษณาจะโหลด (จากที่เห็นใน error log ก่อนหน้านี้ เครื่องของคุณมีการบล็อกคำขอจาก `googleads.g.doubleclick.net` อยู่แล้วบางส่วน ซึ่งเป็นสัญญาณว่ามีตัวบล็อกโฆษณาทำงานอยู่บ้างแล้ว)
2. **ใช้บัญชี YouTube Premium** ล็อกอินบนเบราว์เซอร์ที่ใช้เปิดจอหลัก — วิธีนี้ปลอดโฆษณา 100% อย่างถูกต้องตามนโยบายของ YouTube เอง ไม่ต้องพึ่งเทคนิคใดๆ เพิ่มเติม

กดปุ่ม "🕘 ประวัติ" บนจอหลักเพื่อดูรายการเพลงที่เล่นไปแล้วทั้งหมดในเซสชันนี้ (เรียงจากล่าสุดไปเก่าสุด) แต่ละรายการจะบอก:
- ใครเป็นคนเพิ่มเพลงนั้น (ถ้ามี)
- สาเหตุที่เปลี่ยนออกจากเพลงนั้น (เล่นจบ / ข้าม / ลบออกจากคิว / เปลี่ยนเพลย์ลิสต์ / เล่นไม่ได้)
- เวลาที่ผ่านมา (เช่น "5 นาทีที่แล้ว")

กด **"+ คิว"** ที่รายการประวัติเพื่อนำเพลงนั้นกลับมาเพิ่มเข้าคิวอีกครั้งได้ทันที และมีปุ่ม **"ล้างประวัติ"** ถ้าต้องการเริ่มใหม่

ระบบยังใช้ประวัตินี้เตือนอัตโนมัติด้วย — ถ้าค้นหา/เพิ่มเพลงที่เพิ่งเล่นไปในช่วง 15 เพลงล่าสุด หรือเพลงที่มีอยู่ในคิวแล้ว จะมี toast แจ้งเตือนขึ้นมา (แต่ยังคงเพิ่มเข้าคิวให้ตามปกติ ไม่ได้บล็อก)

ประวัติจะถูกบันทึกไว้ใน `localStorage` ของเบราว์เซอร์เครื่องที่เป็นจอหลัก (คงอยู่แม้ปิดแท็บ/รีสตาร์ทเบราว์เซอร์ จนกว่าจะกดล้างประวัติเอง)

## ล็อกห้องด้วยรหัส PIN

ค่าเริ่มต้นคือ **ไม่ล็อก** — ใครก็ตามที่มีลิงก์/QR หรือรหัสห้องจะเข้าคุมคิวได้ทันที ถ้าต้องการกันคนแปลกหน้าเข้ามาป่วนคิว (เช่น ใช้ในงานเปิด หรือ Wi-Fi สาธารณะที่คนนอกอาจดักลิงก์ได้) ให้เปิดใช้งานได้จากปุ่ม "📱 รีโมทมือถือ" บนจอหลัก:

1. ติ๊กช่อง **"ล็อกห้องด้วยรหัส PIN"** — ระบบจะสุ่มรหัส PIN 4 หลักให้อัตโนมัติ (ใช้กับ **รีโมทผู้ใช้ทั่วไป** เท่านั้น — รีโมทแอดมินไม่ต้องพึ่ง PIN นี้ ดูหัวข้อถัดไป)
2. QR Code จะฝัง PIN ไว้ในลิงก์ให้แล้ว — คนที่ **สแกน QR โดยตรง** จะเข้าห้องได้เลยโดยไม่ต้องพิมพ์ PIN เอง
3. คนที่ได้ **รหัสห้องแบบพิมพ์เอง** (ไม่ได้สแกน QR) จะต้องกรอกรหัส PIN ในช่อง "รหัส PIN" ที่หน้ารีโมทด้วย ถ้าใส่ผิดจะขึ้นข้อความแจ้งเตือนและไม่ได้เข้าห้อง
4. กด **"สุ่มใหม่"** เพื่อเปลี่ยนรหัส PIN ได้ทุกเมื่อ (อุปกรณ์ที่เชื่อมต่ออยู่แล้วก่อนหน้าจะไม่หลุด — ใช้ตรวจสอบเฉพาะตอนเชื่อมต่อครั้งแรกเท่านั้น)
5. ปิดล็อกได้ตลอดเวลาโดยติ๊กออกจากช่องเดิม

รหัส PIN จะคงอยู่ตลอด session ของแท็บจอหลัก (เหมือนรหัสห้อง) และรีเซ็ตใหม่เมื่อปิดแท็บ/เปิดแอปใหม่

## รีโมทแอดมิน vs รีโมทผู้ใช้ทั่วไป (QR แยกกัน)

ปุ่ม "📱 รีโมทมือถือ" บนจอหลักตอนนี้แสดง **QR สองชุดแยกกัน**:

| | 👤 รีโมทผู้ใช้ทั่วไป | 👑 รีโมทแอดมิน |
|---|---|---|
| ค้นหา/เพิ่มเพลง | ✅ | ✅ |
| ลบ/ยกเลิกเพลงของตัวเอง | ✅ | ✅ |
| ปรับจังหวะ (Tempo) | ✅ | ✅ |
| ปรับระดับเสียง / ปิดเสียง | ✅ | ✅ |
| เล่น/หยุด, ข้าม, ก่อนหน้า | ❌ | ✅ |
| จัดเรียงคิว / แทรกเล่นถัดไป | ❌ | ✅ |
| เปิดเพลย์ลิสต์จากรีโมท | ❌ | ✅ |
| ต้องมี PIN ห้อง (ถ้าเปิดใช้) | ต้องมี | ไม่ต้อง (มีรหัสแอดมินของตัวเองแทน) |

**วิธีใช้:** แจก QR "รีโมทผู้ใช้ทั่วไป" ให้เพื่อนทุกคนตามปกติ ส่วน QR/ลิงก์ "รีโมทแอดมิน" ให้แจกเฉพาะคนที่ไว้ใจให้ช่วยควบคุมเพลง (เช่น ผู้ช่วยงาน/เจ้าของงาน) เพราะสิทธิ์แอดมินควบคุมได้ทุกอย่างเหมือนนั่งอยู่ที่จอหลัก

- ลิงก์แอดมินมี **รหัสลับ (admin token)** ฝังอยู่ในตัวเอง แยกจากรหัส PIN ของผู้ใช้ทั่วไปโดยสิ้นเชิง ต่อให้ปิด/เปิด PIN ก็ไม่กระทบสิทธิ์แอดมิน
- กด **"สุ่มรหัสแอดมินใหม่ (ยกเลิก QR เดิม)"** เพื่อทำให้ QR/ลิงก์แอดมินชุดเก่าใช้ไม่ได้อีกต่อไป (คนที่เชื่อมต่ออยู่แล้วจะไม่ถูกตัดสิทธิ์ทันที แต่ลิงก์เดิมจะเชื่อมต่อใหม่ไม่ได้แล้ว)
- หน้ารีโมทที่เชื่อมต่อด้วยสิทธิ์แอดมินจะมีป้าย "👑 แอดมิน" และปุ่มควบคุมเพิ่มเติม (เล่น/หยุด/ข้าม/ก่อนหน้า, จัดเรียงคิว, เปิดเพลย์ลิสต์) ปรากฏขึ้นให้อัตโนมัติ
- การเปลี่ยนรหัส PIN/รหัสแอดมินเอง (ตั้งค่าความปลอดภัยของห้อง) ทำได้จากจอหลักเท่านั้น แม้แต่รีโมทแอดมินก็ไม่สามารถเปลี่ยนได้จากระยะไกล เพื่อป้องกันมือถือที่หลุดไปตกอยู่ในมือคนอื่นมาแก้ไขความปลอดภัยของห้อง

## API Key เริ่มต้นสำหรับค้นหาเพลง

ระบบมาพร้อม YouTube Data API Key เริ่มต้นให้แล้ว ใช้ค้นหาเพลงด้วยคำได้ทันทีโดยไม่ต้องตั้งค่าอะไรเพิ่ม สามารถเปลี่ยนเป็น API Key ของตัวเองได้ทุกเมื่อจากช่อง "ตั้งค่า API Key" ในหน้าค้นหา (ทั้งจอหลักและรีโมท) — ค่าที่บันทึกเองจะมีผลเหนือค่าเริ่มต้นทันที

⚠️ **ข้อควรระวัง:** API Key ที่ฝังมาเป็นค่าเริ่มต้นนี้ปรากฏอยู่ในโค้ดที่ทุกคนเข้าถึงได้ (เพราะเป็นเว็บฝั่ง client ล้วน) หากมีคนนำ Key นี้ไปใช้เกินโควตา การค้นหาอาจหยุดทำงานชั่วคราว แนะนำให้ไปที่ [Google Cloud Console](https://console.cloud.google.com/) แล้ว **จำกัดสิทธิ์ของ Key** (API restrictions → เลือกเฉพาะ "YouTube Data API v3", และ/หรือ HTTP referrer restrictions ให้ใช้ได้เฉพาะโดเมนที่โฮสต์เว็บนี้) หรือสร้าง Key ใหม่ของตัวเองมาใส่แทนเพื่อความปลอดภัยและเสถียรภาพในระยะยาว

## ซ่อน/แสดงคิวเพลง (จอหลัก)

กดปุ่ม "🗂️ ซ่อนคิว" ที่ header ของจอหลัก เพื่อซ่อนแผงคิวเพลงชั่วคราวและขยายวิดีโอให้เต็มจอ (เหมาะเวลาต้องการโฟกัสที่วิดีโอล้วนๆ เช่น ตอนถ่ายภาพ/ถ่ายวิดีโอบรรยากาศงาน) กดซ้ำ "🗂️ แสดงคิว" เพื่อดึงกลับมา ไม่กระทบข้อมูลคิวเพลงใดๆ

## โหมดเต็มจอของแอป + ซ่อน/แสดงเมนูด้วยการแตะจอ (จอหลัก)

- ปุ่ม **"⛶ เต็มจอ"** ที่ header ใช้ Fullscreen API ของเบราว์เซอร์ขยาย**ทั้งหน้าแอป** (header, จอวิดีโอ, แผงคิว ฯลฯ) ให้เต็มจอไปพร้อมกัน — คนละแบบกับปุ่มเต็มจอของตัว YouTube player เอง (ซึ่งจะขยายแค่กรอบวิดีโอ ไม่รวม UI ของแอป) กดซ้ำหรือกด Esc เพื่อย่อกลับ
- แถบเล็กๆ ใต้ header (มีลูกศร ▲/▼) กดเพื่อซ่อน/แสดงแถบเมนูด้านบนได้ตลอดเวลา เหมาะเวลาต้องการให้วิดีโอเต็มพื้นที่จอมากขึ้นโดยไม่ต้องออกจากโหมดเต็มจอ
- **แตะที่แถบ "กำลังเล่น" (ด้านล่าง) หรือแถบ "ถัดไป" (ด้านบน) ของวิดีโอ** ก็ซ่อน/แสดงเมนูได้เช่นกัน ส่วนการแตะตรงกลางวิดีโอโดยตรง (บนตัวเล่น YouTube เอง) ระบบจะพยายามตรวจจับผ่านการเปลี่ยนโฟกัสของหน้าต่างเพื่อซ่อน/แสดงเมนูให้เช่นกัน แต่เนื่องจากข้อจำกัดด้านความปลอดภัยของเบราว์เซอร์ (iframe ของ YouTube เป็นคนละ origin กับหน้าเว็บเรา) จึงอาจไม่แม่นยำ 100% ในทุกกรณี — ถ้าแตะกลางวิดีโอแล้วเมนูไม่ซ่อน/แสดงตามที่ต้องการ ให้ใช้แถบเล็กๆ ▲/▼ ใต้ header แทน ซึ่งใช้งานได้แน่นอนทุกครั้ง

## โลโก้/ไอคอนแอป

เปลี่ยนมาใช้โลโก้ "Sri Karaoke" ที่ให้มา ทั้งใน header ของจอหลักและรีโมท รวมถึงไอคอนแอป (PWA) ตอนติดตั้งลงมือถือ/ทีวี หากต้องการเปลี่ยนโลโก้อีกครั้งในอนาคต แค่แทนที่ไฟล์ `icons/icon-192.png` และ `icons/icon-512.png` ด้วยไฟล์ใหม่ (ขนาดเท่าเดิม) ระบบจะดึงไปใช้เองทั้งหมดโดยไม่ต้องแก้โค้ด

## ป๊อปอัพข้อมูลเว็บไซต์/ลิขสิทธิ์ (แสดงทุกครั้งที่เปิดหน้า)

ทั้งจอหลักและรีโมทจะแสดงป๊อปอัพข้อมูลเกี่ยวกับเว็บไซต์และคำชี้แจงเรื่องลิขสิทธิ์ทุกครั้งที่เปิด/รีเฟรชหน้า (ไม่มีการจดจำว่าเคยกดยอมรับแล้ว) มีปุ่มให้เลือก 3 ปุ่ม:

- **"ยกเลิก"** — ระบบจะพยายามปิดแท็บให้อัตโนมัติ (ใช้ได้เฉพาะกรณีที่เบราว์เซอร์อนุญาต) หากปิดไม่ได้จะเปลี่ยนหน้าจอเป็นข้อความแจ้งให้ปิดแท็บด้วยตนเอง และบล็อกการใช้งานหน้านั้นต่อไป
- **"คุณสมบัติ"** — สลับเนื้อหาในป๊อปอัพจาก "เกี่ยวกับเว็บไซต์/ลิขสิทธิ์" ไปเป็น **รายละเอียดความสามารถและฟีเจอร์ทั้งหมดที่ระบบรองรับ** (แบ่งหมวดตามการค้นหาเพลง, การจัดการคิว, รีโมทมือถือ, การควบคุมการเล่น, และความสะดวกในการใช้งาน) กดซ้ำเพื่อสลับกลับไปดูข้อมูลเว็บไซต์เดิมได้
- **"เข้าสู่ระบบ"** — ปิดป๊อปอัพแล้วเข้าใช้งานตามปกติ (ใช้ได้จากทั้งสองมุมมอง ไม่ต้องสลับกลับไปหน้าแรกก่อน)

ต้องการแก้ไขข้อความในป๊อปอัพนี้ ให้แก้ไขได้ตรงๆ ในไฟล์ `index.html` และ `remote.html` ที่ส่วน `<div class="disclaimer-overlay" id="disclaimer-modal">` — เนื้อหาข้อมูลเว็บไซต์อยู่ใน `#disclaimer-panel-about` ส่วนเนื้อหาคุณสมบัติอยู่ใน `#disclaimer-panel-features`

## Screensaver ตอนไม่มีเพลงเล่น

เมื่อคิวว่างหรือยังไม่มีเพลงเล่น (จอหลัก) แทนที่จะเป็นพื้นหลังนิ่งๆ ตอนนี้จะมีบรรยากาศห้องคาราโอเกะให้ดูระหว่างรอ:
- **สปอตไลท์เวที 3 ดวง** สีขาว/ชมพู/ฟ้า ส่ายกวาดไปมาจากด้านบนของจอ แต่ละดวงมีจังหวะและมุมส่ายไม่เท่ากัน ให้ดูเป็นธรรมชาติ
- **แสงวาบสั้นๆ** เป็นระยะเมื่อสปอตไลท์ส่ายมาทางกล้อง/คนดู (ทุกๆ ~6.5 วินาที ตั้งใจให้ห่างและเบาพอที่จะไม่รบกวนสายตาหรือเสี่ยงกับคนที่ไวต่อแสงกระพริบ)
- **จุดแสงสีคมชัด 4 สี** (ชมพู/ทอง/ฟ้า/ม่วง) ลอยเคลื่อนไหวช้าๆ ใช้ไล่โทนสีแบบ radial-gradient แทนการเบลอทั้งดวง ทำให้แสงดูมีขอบชัดเจนและสดใสกว่าเดิม
- **ไฟกระพริบเล็กๆ 12 จุด** รอบขอบจอ คล้ายไฟประดับ/ไฟดวงเล็กในห้องคาราโอเกะ กระพริบไม่พร้อมกันให้ดูมีชีวิตชีวา
- โลโก้ Sri Karaoke ลอยเคลื่อนที่วนไปรอบจอแบบสุ่มทิศทาง (คล้าย DVD screensaver)
- ปุ่ม "เริ่มระบบ" และข้อความต้อนรับอยู่ในกล่องโปร่งแสงตรงกลางจอ อ่านง่ายแม้พื้นหลังเคลื่อนไหว
- ถ้าเบราว์เซอร์/อุปกรณ์ของผู้ใช้ตั้งค่า "ลดการเคลื่อนไหว" (`prefers-reduced-motion`) ไว้ ระบบจะปิดอนิเมชันและแสงวาบทั้งหมดให้อัตโนมัติ เพื่อความปลอดภัยของคนที่ไวต่อแสงกระพริบ

เอฟเฟกต์ทั้งหมดเป็น CSS animation ล้วน ไม่กินทรัพยากรเครื่องมาก ปรับสี/ความเร็ว/มุมส่ายได้ที่ `.spotlight`, `.disco-dot`, `.led`, `#screensaver-logo` และ `@keyframes` ที่เกี่ยวข้องในไฟล์ `index.html`

## ข้อจำกัดที่ควรทราบ

- ต้องเชื่อมต่ออินเทอร์เน็ตตลอดการใช้งาน (สำหรับ YouTube, PeerJS broker, และ Google Fonts)
- เพลย์ลิสต์บันทึกไว้ในเครื่องที่เป็น "จอหลัก" เท่านั้น (ผ่าน localStorage) ไม่ได้ซิงก์ข้ามอุปกรณ์
- หากปิด/รีเฟรชหน้าจอหลัก รหัสห้องจะเปลี่ยนใหม่ทุกครั้ง ต้องสแกน QR ใหม่
