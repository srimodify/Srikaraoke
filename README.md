# Sri Karaoke 🎤

แอปคาราโอเกะที่ดึงเพลงจากยูทูบมาแสดงบนจอทีวี พร้อมให้เพื่อน ๆ สแกน QR Code เพื่อค้นหาและเพิ่มเพลงเข้าคิวจากมือถือของตัวเอง

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` + `app.js` | หน้าจอหลัก แสดงผลบนทีวี/จอใหญ่ — เล่นวิดีโอ, แสดงคิว, สร้าง QR Code |
| `remote.html` + `remote.js` | หน้ารีโมทสำหรับมือถือ — ค้นหาเพลง, จัดการคิว |
| `screen2.html` + `screen2.js` | หน้า **จอที่ 2** (ทางเลือก) — วิดีโอเต็มจอ + ชื่อเพลง + คะแนน ไม่มีปุ่มควบคุม |
| `manifest.json` / `manifest-remote.json` / `manifest-screen2.json` | ไฟล์ตั้งค่า PWA ของแต่ละหน้า |
| `sw.js` | Service Worker สำหรับติดตั้งเป็นแอปและใช้งานแบบออฟไลน์บางส่วน |
| `icons/` | ไอคอนแอป |
| `assets/please-select-song.mp3` | เพลงคลอที่เล่นวนตอนคิวว่าง (แทนที่ไฟล์นี้เพื่อเปลี่ยนเสียงเอง) |
| `sound-effects/manifest.json` + `sound-effects/*.mp3` | เสียงเอฟเฟกต์ + รายชื่อไฟล์ (แก้ manifest.json เพื่อเพิ่ม/ลบเสียง) |
| `manual.html` | หน้าอ่านคู่มือการใช้งาน (เปิดจากปุ่ม "📖 คู่มือการใช้งาน" ในหน้าต้อนรับ) — สร้างจาก `คู่มือการใช้งาน.md` |
| `คู่มือการใช้งาน.md` | ต้นฉบับคู่มือการใช้งาน (แก้ที่ไฟล์นี้ แล้วสร้าง `manual.html` ใหม่) |
| `tools/build-manual.py` | สคริปต์สร้าง `manual.html` จาก `คู่มือการใช้งาน.md` (ใช้เฉพาะตอนแก้คู่มือ ไม่ได้ใช้ตอนรันเว็บ — ต้อง `pip install markdown`) |

## วิธีการทำงาน

- จอหลักและมือถือแต่ละเครื่องเชื่อมต่อกันแบบ **peer-to-peer (WebRTC)** ผ่านไลบรารี PeerJS โดยไม่ต้องมีเซิร์ฟเวอร์ของตัวเอง
- เมื่อเปิด `index.html` บนทีวี ระบบจะสุ่ม **รหัสห้อง** และสร้าง QR Code ที่มีลิงก์ไปยัง `remote.html?room=...`
- เพื่อนสแกน QR ด้วยกล้องมือถือ → เบราว์เซอร์เปิด `remote.html` → เชื่อมต่อกับจอหลักอัตโนมัติ
- การเพิ่ม/ลบ/ข้าม/แทรกเพลง จะซิงก์ไปยังทุกอุปกรณ์ที่เชื่อมต่ออยู่แบบเรียลไทม์

⚠️ **สำคัญ:** เพราะใช้ QR Code ที่เป็นลิงก์เว็บ ต้อง **โฮสต์ไฟล์ทั้งหมดไว้บนเว็บเซิร์ฟเวอร์** (ไม่ใช่เปิดไฟล์ตรง ๆ แบบ `file://`) มือถือถึงจะเปิดลิงก์และสแกน QR ได้ วิธีที่ง่ายที่สุด:

### วิธีที่ 1 — โฮสต์ฟรีบนอินเทอร์เน็ต (แนะนำ)
อัปโหลดโฟลเดอร์นี้ขึ้น GitHub Pages, Netlify, Vercel หรือ Cloudflare Pages (ลากไฟล์วางก็ใช้ได้ทันที) แล้วเปิด `index.html` ผ่าน URL ที่ได้บนจอทีวี/คอมที่ต่อจอทีวี

### วิธีที่ 2 — รันในวงแลนบ้าน (ไม่ต้องต่อเน็ตนอกบ้าน)
บนเครื่องที่ต่อกับจอทีวี เปิด Terminal ในโฟลเดอร์นี้แล้วรัน:
```bash
python3 -m http.server 8000
```
จากนั้นเปิดเบราว์เซอร์บนทีวี/กล่องแอนดรอยไปที่ `http://<IP เครื่องนี้ในวงแลน>:8000/index.html`
มือถือที่ต่อ Wi-Fi วงเดียวกันจะสแกน QR แล้วเข้าถึง `remote.html` ได้ปกติ (ต้องเชื่อมต่ออินเทอร์เน็ตด้วย เพราะ PeerJS และ YouTube ต้องใช้เน็ต)

⚠️ วิธีนี้เป็น HTTP ธรรมดา (ไม่ใช่ HTTPS) แอปจะแสดงแบนเนอร์เตือนและการเชื่อมต่อรีโมทอาจไม่เสถียรเท่าที่ควร ใช้ได้สำหรับทดสอบ/งานเล็กๆ ในบ้าน แต่ถ้าจะใช้งานจริงจัง แนะนำวิธีที่ 1 (โฮสต์บน HTTPS ฟรี) หรือใช้เครื่องมืออย่าง `ngrok`/`cloudflared` เปิดทันเนล HTTPS ชั่วคราวมาที่เครื่องในบ้านแทน

## การติดตั้งเป็นแอป (PWA)

- **บนทีวี/กล่องแอนดรอย:** เปิด `index.html` ด้วย Chrome แล้วเลือก "ติดตั้งแอป" หรือ "Add to Home screen"
- **บนมือถือ:** เปิดลิงก์รีโมท (จากการสแกน QR) แล้วเลือก "เพิ่มลงหน้าจอหลัก" — ครั้งต่อไปเปิดจากไอคอนแอปได้เลย
- **บนจอที่ 2:** เปิด `screen2.html` ด้วย Chrome แล้วเลือก "ติดตั้งแอป" ได้เช่นเดียวกับจอหลัก (ก่อนหน้านี้ติดตั้งไม่ได้เพราะขาดการลงทะเบียน Service Worker — **แก้ไขแล้ว**)

⚠️ **เงื่อนไขการติดตั้งที่ควรรู้** (เป็นมาตรฐานของเบราว์เซอร์ ไม่ใช่ข้อจำกัดของเว็บนี้):
- ต้องเข้าเว็บผ่าน **HTTPS** เท่านั้น (GitHub Pages ใช้ HTTPS เป็นค่าเริ่มต้นอยู่แล้ว)
- ต้องมี **Service Worker ลงทะเบียนสำเร็จ** — ถ้าเบราว์เซอร์/เครือข่ายบล็อกการโหลดไฟล์ `sw.js` (เช่น ตัวบล็อกโฆษณาบางตัวที่เข้มงวดมาก) จะติดตั้งไม่ได้
- เบราว์เซอร์บางตัว/บางเวอร์ชันเก่ามากอาจไม่รองรับการติดตั้ง PWA เลย (โดยเฉพาะเบราว์เซอร์ในตัวของกล่อง Android TV รุ่นเก่า) — ดูหัวข้อ "เบราว์เซอร์เก่าไม่รองรับ" ถ้าเจอปัญหานี้
- **iOS/iPadOS (Safari)** ไม่ต้องพึ่ง Service Worker ในการติดตั้ง (ใช้ "Add to Home Screen" ได้แม้ไม่มี Service Worker) แต่ยังต้องพึ่ง Service Worker สำหรับการทำงานแบบออฟไลน์อยู่ดี

## การค้นหาเพลง

- **วางลิงก์ YouTube โดยตรง** ในช่องค้นหาบนรีโมท ใช้งานได้ทันทีโดยไม่ต้องตั้งค่าอะไร
- **ค้นหาด้วยคำ** (เช่น พิมพ์ชื่อเพลง) ต้องมี YouTube Data API Key ฟรี:
  1. ไปที่ [Google Cloud Console](https://console.cloud.google.com/)
  2. สร้างโปรเจกต์ใหม่ → เปิดใช้งาน "YouTube Data API v3"
  3. สร้าง API Key แล้วคัดลอกมาใส่ในแท็บ "ตั้งค่า" บนหน้ารีโมท

**หมายเหตุด้านความปลอดภัย:** ระบบมี API Key เริ่มต้นฝังมาให้ใช้งานได้ทันทีโดยไม่ต้องตั้งค่าอะไร — ค่านี้เข้ารหัสแบบ Base64 ไว้ในซอร์สโค้ด (ไม่ใช่ plaintext ตรงๆ) เพื่อป้องกันการถูกบอทสแกนหาคีย์อัตโนมัติหากซอร์สโค้ดถูกเผยแพร่เป็น public repository — **แต่ไม่ใช่การเข้ารหัสที่ปลอดภัยแท้จริง** เนื่องจากเป็นเว็บแอปที่รันบนเบราว์เซอร์ฝั่งไคลเอนต์ล้วนๆ ไม่มีเซิร์ฟเวอร์เบื้องหลัง ผู้ที่ตั้งใจเปิด Developer Tools ดู network request ก็ยังสามารถเห็นคีย์ได้อยู่ดี (ข้อจำกัดของเทคโนโลยีเว็บฝั่งไคลเอนต์ ไม่ใช่ข้อบกพร่องของโค้ด)

**เลือกได้ว่าจะค้นหาแบบไหน** (ปุ่มเลือกโหมดอยู่เหนือช่องค้นหา ทั้งจอหลักและรีโมท):
- **🎤 เพลงทั่วไป** — ค้นหาตามคำที่พิมพ์ตรงๆ (มักเจอเวอร์ชันต้นฉบับที่มีเสียงนักร้อง)
- **🎵 คาราโอเกะ** (ค่าเริ่มต้น) — เติมคำว่า "karaoke" ต่อท้ายคำค้นให้อัตโนมัติ เพื่อเจอเวอร์ชันดนตรีไม่มีเสียงร้อง/มีเนื้อเพลงขึ้นจอ

เลือกโหมดค้างไว้ได้ (จอหลักจำไว้ตลอดเซสชัน, รีโมทจำไว้ในเครื่องนั้นข้ามวันไปเลย) ไม่ต้องเลือกใหม่ทุกครั้งที่ค้นหา

ถ้าลบข้อความในช่องค้นหาจนว่างเปล่า รายการผลการค้นหาเดิมจะหายไปด้วยอัตโนมัติ (ทั้งจอหลักและรีโมท) ไม่ค้างอยู่ให้สับสนว่าเป็นผลจากคำค้นไหน

ในหน้าค้นหาของจอหลัก ข้างปุ่ม "🎵 เพลงแนะนำ" มีปุ่ม **"🔥 ยอดนิยม"** ให้ดูเพลงที่เพิ่งเล่นไปแล้วในคืนนี้ได้ในตัว โดยไม่ต้องออกจากหน้าค้นหา (รายละเอียดอยู่ในหัวข้อ "ประวัติเพลงที่เล่นไปแล้ว" ด้านล่าง)

## ฟีเจอร์ที่รองรับ

- ✅ เล่นวิดีโอจาก YouTube ผ่าน YouTube IFrame Player
- ✅ **เล่นเพลงถัดไปในคิวอัตโนมัติเมื่อเพลงจบ** และ **ลบเพลงที่เล่นจบ/ถูกข้ามออกจากคิวให้อัตโนมัติ**
- ✅ **ชื่อเพลงที่กำลังเล่นวิ่งจากขวาไปซ้ายทับด้านล่างวิดีโอ** พื้นหลังโปร่งใส ไม่บดบังวิดีโอ
- ✅ **แสดงชื่อเพลงถัดไปล่วงหน้า** ที่มุมบนของจอ **ในช่วง 15 วินาทีสุดท้ายก่อนเพลงปัจจุบันจะจบ** หรือแจ้งเตือน "ไม่มีเพลงในคิว...กรุณาเลือกเพลง" ถ้าไม่มีเพลงต่อคิว
- ✅ ค้นหาเพลงได้จาก **จอหลักโดยตรง** — ใช้งานแบบจอเดียวได้เต็มรูปแบบโดยไม่ต้องมีใครสแกน QR ก็ค้นหาและกด "เล่นเลย"/"+ คิว" ได้
- ✅ ผลการค้นหาแสดงภาพตัวอย่างย่อ (thumbnail) พร้อมชื่อเพลง/ช่อง ทั้งบนจอหลักและรีโมท
- ✅ **เลือกโหมดค้นหาได้: เพลงทั่วไป (มีเสียงร้อง) หรือคาราโอเกะ** ทั้งจอหลักและรีโมท
- ✅ ระบบคิวเพลง: เพิ่ม, ลบ, แทรกเล่นถัดไป, **จัดเรียงลำดับคิวได้** (ลากวางด้วยเมาส์ หรือกดปุ่ม ▲▼ — ใช้งานบนจอหลัก)
- ✅ จัดการเพลย์ลิสต์: บันทึกคิวปัจจุบันเป็นเพลย์ลิสต์ และโหลดกลับมาใช้ภายหลัง (จอหลัก)
- ✅ ปรับจังหวะ (Tempo) ของเพลงที่กำลังเล่นได้ **ทั้งจากจอหลักและรีโมท**
- ✅ สแกน QR Code เพื่อควบคุมผ่านมือถือหลายเครื่องพร้อมกัน
- ✅ **รีโมทแอดมิน แยก QR จากรีโมทผู้ใช้ทั่วไป** — แจกสิทธิ์ควบคุมเต็มรูปแบบให้เฉพาะคนที่ไว้ใจ
- ✅ **ล็อกห้องด้วยรหัส PIN** (ทางเลือก) กันคนแปลกหน้าที่ไม่มีลิงก์เข้ามาคุมคิว
- ✅ **API Key ค้นหาเพลงมาให้พร้อมใช้งานทันที** (เปลี่ยนเป็นของตัวเองได้ตลอดเวลา)
- ✅ **ซ่อน/แสดงคิวเพลงบนจอหลักได้** เพื่อโฟกัสที่วิดีโอเต็มจอ
- ✅ **โหมดเต็มจอของแอป** (ไม่ใช่แค่ของ YouTube) พร้อม**ซ่อน/แสดงเมนูด้วยการแตะจอ**
- ✅ **แสดงคอร์ดกีตาร์ของเพลงที่กำลังเล่น** เป็นแถบเลื่อนไฮไลต์ตามจังหวะเพลงทับจอวิดีโอ ทั้งจอหลักและจอที่ 2 พิมพ์เตรียมไว้เอง ใช้ได้ทั้ง YouTube และไฟล์ในเครื่อง
- ✅ **ปุ่มออกจากระบบพร้อมป๊อปอัพยืนยัน** ตัดการเชื่อมต่อทุกอย่างให้เรียบร้อยก่อนปิด
- ✅ **ระบบจอที่ 2** (ทางเลือก) — จอแสดงผลเสริมไร้สาย โชว์วิดีโอเต็มจอ + ชื่อเพลง + คะแนน แยกจากจอหลัก
- ✅ **เล่นเพลงจากไฟล์ในเครื่องได้** นอกจาก YouTube — ค้นหารวมกัน มีป้ายบอกแหล่งที่มา (🌐/💻)
- ✅ **ไฟล์ MP3 ที่มีเนื้อเพลงฝังอยู่ → แสดงเนื้อเพลงไล่สีทีละคำแบบคาราโอเกะอัตโนมัติ** พร้อมภาพปกถ้ามี ซิงก์ไปจอที่ 2 ด้วย
- ✅ **เลือกได้ว่าเสียงจะออกจอหลักหรือจอที่ 2**
- ✅ **เปิด/ปิดระบบให้คะแนนร้องเพลงได้เอง** ในเมนูตั้งค่า
- ✅ **เลือกโหมดการแสดงผลได้หลังเข้าระบบ** (จอหลัก/จอที่ 2/รีโมท) จากลิงก์เดียว ไม่ต้องจำ URL แยกไฟล์
- ✅ **หน้าจอ "กำลังเริ่มเล่น" คั่นระหว่างเปลี่ยนเพลง** ปิดเสียงของ player จริงไว้เงียบสนิทระหว่างรอ (กันเสียงโฆษณา) ทั้งจอหลักและจอที่ 2
- ✅ **เพลงคลอ "กรุณาเลือกเพลง" วนลูปตอนคิวว่าง** จนกว่าจะมีเพลงเข้าคิว
- ✅ **เสียงเอฟเฟกต์** มีให้พร้อมใช้ 10 เสียง (ปรบมือ หัวเราะ ว้าว ฯลฯ) พร้อมไอคอนอีโมจิ กดได้จากจอหลักและรีโมท เพิ่มเองได้ไม่ต้องแก้โค้ด
- ✅ **คอนเฟตติ้ + ปุ่มส่งอิโมจิลอย** (26 แบบ) สร้างบรรยากาศสนุกสดระหว่างงาน
- ✅ **ข้อความฝากถึงเพลง + โหวตเพลงถัดไป** เพิ่มการมีส่วนร่วมจากผู้ร้องทุกคน
- ✅ **หน้าจอสรุปค่ำคืนนี้** อัตโนมัติตอนเริ่มงานใหม่ — นักร้องยอดเยี่ยม/เพลงฮิต/คะแนนสูงสุด
- ✅ **ธีมสี 5 แบบ** (มืด/สว่าง/วันเกิด/ปีใหม่/สงกรานต์) พร้อมไอคอนลอยประดับตามเทศกาล
- ✅ **ภาพพื้นหลังตอนคิวว่าง** ตั้งเองได้ สไลด์โชว์ตั้งเวลาได้ ส่งไปจอที่ 2 อัตโนมัติ
- ✅ **กล้องสด (เว็บแคม) เป็นพื้นหลัง** ตอนคิวว่าง + หน้า MP3 + หน้าต่างเล็กตอนเล่นวิดีโอ เปิด/ปิดที่จอหลักและจอที่ 2 แยกกันได้ กล้องหลุดก็กลับไปสไลด์โชว์/ไฟดิสโก้เอง
- ✅ **ช่องเสียง Stereo / L+L / R+R** สำหรับไฟล์ในเครื่อง (แผ่นคาราโอเกะที่แยกเสียงร้อง/ดนตรีซ้าย-ขวา) และ **ส่งเสียงไฟล์ในเครื่องไปออกจอที่ 2** ได้
- ✅ **ปุ่ม "📖 คู่มือการใช้งาน"** ในหน้าต้อนรับ เปิดอ่านคู่มือฉบับเต็มในแท็บใหม่
- ✅ **"ห้องคาราโอเกะสำรอง"** ลิงก์ด่วนไปเว็บคาราโอเกะอื่นๆ พร้อมไอคอน ในหน้าเลือกโหมดการแสดงผล เผื่อกรณีฉุกเฉิน
- ✅ **เริ่มงานใหม่ได้ในคลิกเดียว** (ล้างคิว/คะแนน/ประวัติ แต่เก็บเพลย์ลิสต์ไว้)
- ✅ **โหมดประหยัดพลัง** ปิดอนิเมชันหนักๆ สำหรับอุปกรณ์จอหลักที่สเปกไม่แรง
- ✅ **สลับธีมมืด/สว่างได้** จำค่าไว้ในเครื่อง (จอวิดีโอยังคงมืดเสมอ)
- ✅ **จัดการ/ตัดการเชื่อมต่ออุปกรณ์รีโมท** ได้จากจอหลักโดยตรง
- ✅ **เชื่อมต่อรีโมทกลับมาอัตโนมัติทันทีที่เปิดจอมือถือ** ไม่ต้องสแกน QR ใหม่
- ✅ **ประวัติเพลงที่เล่นไปแล้ว** พร้อมเหตุผลที่เปลี่ยนเพลง เวลาที่ผ่านมา และปุ่มเพิ่มกลับเข้าคิว
- ✅ **สำรอง/กู้คืนข้อมูลทั้งหมด** (เพลย์ลิสต์ + ประวัติ) เป็นไฟล์ .json เดียว
- ✅ รองรับภาษาไทยเต็มรูปแบบ (ฟอนต์ Kanit / Sarabun)
- ✅ ติดตั้งเป็นแอป (PWA) ได้ทั้งจอทีวีและมือถือ
- ✅ รองรับหน้าจอแนวตั้งและแนวนอน (responsive)
- ✅ นำทางด้วยรีโมททีวี/กล่องแอนดรอย — ปุ่มทุกปุ่มโฟกัสได้ด้วย D-pad, รองรับปุ่ม Back/ปุ่มสื่อ (เล่น/หยุด/ข้าม)

## สิทธิ์การควบคุม (จอหลัก vs รีโมทแอดมิน vs รีโมทผู้ใช้ทั่วไป)

เพื่อไม่ให้เพลงที่กำลังเล่นถูกสลับ/ข้ามโดยไม่ได้ตั้งใจจากมือถือหลายเครื่องพร้อมกัน จึงแบ่งสิทธิ์เป็น 3 ระดับ:

| การทำงาน | จอหลัก | 👑 รีโมทแอดมิน | 👤 รีโมทผู้ใช้ทั่วไป |
|---|:---:|:---:|:---:|
| ค้นหา/เพิ่มเพลงเข้าคิว | ✅ | ✅ | ✅ |
| ลบ/ยกเลิกเพลงออกจากคิว | ✅ | ✅ | ✅ |
| ปรับจังหวะ (Tempo) | ✅ | ✅ | ✅ |
| ปรับระดับเสียง / ปิดเสียง | ✅ | ✅ | ✅ |
| เล่น/หยุด, ข้าม, ก่อนหน้า | ✅ | ✅ | ❌ (แสดงผลอย่างเดียว) |
| จัดเรียงลำดับคิว / แทรกเล่นถัดไป | ✅ | ✅ | ❌ (ดูคิวได้อย่างเดียว) |
| เปิดเพลย์ลิสต์ | ✅ | ✅ | ❌ (ดูรายชื่อได้อย่างเดียว) |
| บันทึกเพลย์ลิสต์ใหม่ | ✅ | ❌ | ❌ |
| เปลี่ยน/ปิดเปิดรหัส PIN และรหัสแอดมิน | ✅ | ❌ | ❌ |

รายละเอียดวิธีแจก QR แอดมิน/ผู้ใช้ทั่วไปอยู่ในหัวข้อ "รีโมทแอดมิน vs รีโมทผู้ใช้ทั่วไป" ด้านล่าง

## คิวคนร้อง (แบ่งคิวเท่าเทียม)

ปกติเพลงจะเข้าคิวตามลำดับที่มีคนเพิ่ม ถ้าคนใดคนหนึ่งเพิ่มเพลงรัวๆ หลายเพลงติดกัน คนอื่นจะต้องรอนาน กดปุ่ม **"👥 คิวคนร้อง: ปิด"** ที่มุมขวาของแผงคิวเพลง (จอหลัก) จะมีป๊อปอัพให้ระบุ**จำนวนเพลง/คน**ได้อิสระ (ค่าเริ่มต้น **1 เพลง/คน**) แล้วกด "เปิดใช้งาน" — ระบบจะจัดเรียงเพลงที่ยังไม่ได้เล่นใหม่แบบสลับคิวกันในแต่ละคนตามจำนวนที่ตั้งไว้ แล้วสลับไปคนถัดไป โดยไม่แตะเพลงที่กำลังเล่นอยู่ กดปุ่มเดิมอีกครั้งเพื่อเปิดป๊อปอัพเดิมได้ตลอด ทั้งปรับจำนวนใหม่หรือกด "ปิดใช้งาน" ก็ได้จากที่เดียวกัน ค่าเริ่มต้นของระบบคือ **ปิด** จึงไม่กระทบพฤติกรรมเดิมถ้าไม่ได้เปิดใช้งาน

## เล่นเพลงถัดไปอัตโนมัติ + ลบเพลงที่เล่นจบออกจากคิว

ตอนนี้เมื่อเพลงที่กำลังเล่นจบลง (หรือถูกกดข้าม หรือเล่นไม่ได้) ระบบจะ:
1. **ลบเพลงนั้นออกจากคิวโดยอัตโนมัติ** (เพลงที่เล่น/ข้ามไปแล้วจะไม่ค้างอยู่ในรายการคิวอีกต่อไป — ยังดูย้อนหลังได้เสมอผ่าน "🕘 ประวัติ")
2. **เล่นเพลงถัดไปในคิวต่อทันที** ถ้ายังมีเพลงเหลืออยู่
3. ถ้าไม่มีเพลงเหลือแล้ว ระบบจะหยุดเล่นและกลับไปที่หน้าจอว่าง (screensaver)

**มุมบนของจอ** จะแสดง **"▶ ถัดไป: [ชื่อเพลง]"** ให้เห็นล่วงหน้า **เฉพาะช่วง 15 วินาทีสุดท้ายก่อนเพลงปัจจุบันจะจบ** เท่านั้น (ไม่ใช่แสดงตลอดทั้งเพลง เพื่อไม่ให้บดบังจอเปล่าๆ ในช่วงที่ยังร้องอยู่) หรือถ้าไม่มีเพลงต่อคิวแล้ว จะขึ้นข้อความเตือน **"⚠️ ไม่มีเพลงในคิว...กรุณาเลือกเพลง"** แทนในช่วงเวลาเดียวกัน เพื่อให้คนคุมจอหลัก/เพื่อนๆ รู้ตัวก่อนเพลงจบและรีบเพิ่มเพลงใหม่ทัน

⚠️ **ผลข้างเคียงที่ควรทราบ:** เพราะเพลงที่เล่นจบจะถูกลบออกจากคิวทันที ปุ่ม **"⏮ ก่อนหน้า"** (ย้อนกลับไปเพลงก่อนหน้า) จะใช้งานไม่ได้อีกต่อไปในสถานการณ์ปกติ เนื่องจากเพลงก่อนหน้าไม่ได้อยู่ในคิวแล้ว (ต้องไปเปิดใหม่จากประวัติแทน) ส่วนการ **"เล่นเลย"** (แทรกเพลงเล่นด่วนแทรกกลางคิว) ยังทำงานตามปกติ — เพลงที่ถูกแทรกแซงจะไม่ถูกลบ แต่จะถูกเลื่อนไปรอเล่นทีหลังแทน ไม่ใช่หายไปเลย

## เพลงแนะนำ

หน้าค้นหาเพลงบนจอหลัก มีปุ่ม **"🎵 เพลงแนะนำ"** อยู่ข้างปุ่ม "ปิด" ด้านล่างของหน้าต่างค้นหา กดเพื่อเปิด/ปิดรายการชิปเพลงยอดนิยมที่แตะแล้วค้นหาได้ทันทีโดยไม่ต้องพิมพ์ (ค่าเริ่มต้นซ่อนไว้ ไม่โชว์ค้างอยู่ตลอดเวลาเหมือนก่อนหน้านี้) แก้ไขรายการเพลงแนะนำได้เองที่ตัวแปร `SUGGESTED_SONGS` ในไฟล์ `app.js` เพื่อปรับให้เหมาะกับกลุ่มคนในงานของคุณ

## ปรับระดับเสียง (จอหลัก + รีโมท)

นอกจากจังหวะ (Tempo) แล้ว ตอนนี้ปรับ **ระดับเสียง** และ **ปิด/เปิดเสียง (mute)** ได้ทั้งจากจอหลักและรีโมททุกคน (เหมือนกับ Tempo) เผื่อใครนั่งไกลทีวีอยากปรับเสียงจากมือถือตัวเองได้เลยโดยไม่ต้องเดินไปที่จอหลัก

## สำรอง/กู้คืนข้อมูลทั้งหมด (เพลย์ลิสต์ + ประวัติ)

ในเมนู **"⚙️ ตั้งค่า"** (จอหลัก) มีปุ่ม:
- **"⬇️ สำรองข้อมูลทั้งหมด (.json)"** — ดาวน์โหลดไฟล์เดียวที่รวม **เพลย์ลิสต์ + ประวัติเพลง** ทั้งหมดที่บันทึกไว้ ใช้สำรองข้อมูลหรือย้ายไปใช้กับเบราว์เซอร์/อุปกรณ์อื่นได้
- **"⬆️ กู้คืนข้อมูล (.json)"** — เลือกไฟล์ที่เคยส่งออกไว้ (หรือไฟล์ที่แชร์กันมา) เพื่อนำเข้ากลับมา โดย:
  - **เพลย์ลิสต์**: ถ้าชื่อซ้ำกับที่มีอยู่แล้ว ระบบจะเติม "(นำเข้า)" ต่อท้ายให้อัตโนมัติเพื่อไม่ให้ข้อมูลเดิมหาย
  - **ประวัติเพลง**: นำเข้าแบบผสานกับประวัติเดิม (ไม่ลบของเก่า) เรียงตามเวลาล่าสุดให้ใหม่
  - รองรับไฟล์เพลย์ลิสต์รุ่นเก่า (ที่ส่งออกก่อนอัปเดตนี้) ด้วยเช่นกัน

## ระบบให้คะแนนร้องเพลง + กระดานผู้นำ

เมื่อเพลงเล่นจบตามธรรมชาติ (ไม่นับกรณีกดข้ามกลางเพลง) ระบบจะ:
1. สุ่มคะแนนร้อง (60–100 คะแนน) พร้อมข้อความให้กำลังใจตามช่วงคะแนน (พยายามได้ดี! / เก่งมาก! / ยอดเยี่ยม! / เพอร์เฟค!)
2. แสดงป๊อปอัพคะแนนใหญ่ๆ กลางจอ ค้างไว้ประมาณ 3.5 วินาที
3. เปลี่ยนเป็นป๊อปอัพ **"🏆 5 อันดับคะแนนสูงสุด"** ค้างไว้อีกประมาณ 4.5 วินาที แล้วปิดตัวเองอัตโนมัติ (แตะที่ป๊อปอัพเพื่อปิดก่อนเวลาได้ทุกเมื่อ)

ป๊อปอัพนี้แสดงทั้งบนจอหลักและส่งไปแสดงบนมือถือของทุกคนที่เชื่อมต่ออยู่ด้วย (ทั้งรีโมทแอดมินและผู้ใช้ทั่วไป) เพื่อความสนุกร่วมกัน คะแนนทั้งหมดถูกเก็บสะสมไว้ใน localStorage ของจอหลัก เพื่อคำนวณอันดับ Top 5 ตลอดการเล่นในเซสชันนั้น

⚠️ หมายเหตุ: คะแนนเป็นการ **สุ่มเพื่อความสนุกเท่านั้น** ไม่ได้วิเคราะห์เสียงร้องจริง เนื่องจากการวิเคราะห์คุณภาพเสียงร้องจริงต้องเข้าถึงไมโครโฟนและประมวลผลเสียงแบบเรียลไทม์ ซึ่งเป็นการพัฒนาเพิ่มเติมนอกเหนือขอบเขตปัจจุบัน

**ปิดระบบนี้ได้** ถ้าไม่ต้องการ — ไปที่ "⚙️ ตั้งค่า" → หัวข้อ "คะแนนร้องเพลง" → ปิดสวิตช์ "🏆 ระบบให้คะแนนร้องเพลง" เพลงที่จบหลังจากนั้นจะไม่มีป๊อปอัพคะแนน/กระดานผู้นำขึ้นมาอีกเลย (ทั้งจอหลัก รีโมท และจอที่ 2) ค่าเริ่มต้นคือ **เปิด** เหมือนพฤติกรรมเดิม



ระบบนี้ปรับ **จังหวะ (Tempo/ความเร็ว)** ได้จริงผ่าน YouTube IFrame API แต่ **ไม่สามารถปรับคีย์เสียง (Pitch) แยกจากจังหวะได้** เนื่องจากข้อจำกัดของแพลตฟอร์ม — วิดีโอ YouTube ที่ฝังผ่าน iframe ไม่อนุญาตให้เว็บภายนอกเข้าถึงข้อมูลเสียงดิบเพื่อประมวลผลปรับคีย์ (เป็นการป้องกันเนื้อหาของ YouTube เอง) หากต้องการฟีเจอร์ปรับคีย์เสียงจริง จะต้องเปลี่ยนแหล่งเสียงจากไฟล์ YouTube ไปเป็นไฟล์เสียง/วิดีโอที่แอปควบคุมโดยตรง (เช่นไฟล์ที่อัปโหลดเอง) แล้วประมวลผลด้วย Web Audio API แทน ซึ่งเป็นการพัฒนาเพิ่มเติมนอกเหนือขอบเขตปัจจุบัน

## ความเสถียรที่ปรับปรุงล่าสุด

- **รหัสห้องไม่เปลี่ยนเมื่อรีเฟรชจอหลัก** — เก็บรหัสห้องไว้ใน session ของแท็บ ถ้าจอหลักหลุด/รีเฟรชกลางงาน QR เดิมยังใช้ต่อได้โดยไม่ต้องสแกนใหม่ (จนกว่าจะปิดแท็บ)
- **รีโมทเชื่อมต่อใหม่อัตโนมัติ** — ถ้า Wi-Fi มือถือหลุดชั่วคราว ระบบจะพยายามเชื่อมต่อกลับให้เองโดยไม่ต้องออกจากหน้าเว็บ (มีแบนเนอร์แจ้งสถานะระหว่างเชื่อมต่อใหม่)
- **แจ้งเตือนเมื่อเปิดผ่าน HTTP** — ทั้งจอหลักและรีโมทจะแสดงแบนเนอร์เตือนถ้าไม่ได้เปิดผ่าน HTTPS (หรือ localhost) เพราะ WebRTC ทำงานไม่เสถียรบน HTTP ธรรมดา
- **ข้ามเพลงอัตโนมัติเมื่อเล่นไม่ได้** — ถ้าวิดีโอถูกลบ/ปิดการฝัง/เล่นไม่ได้ ระบบจะแจ้งเตือนบนจอหลักแล้วข้ามไปเพลงถัดไปให้อัตโนมัติ แทนที่จะค้าง
- **ปุ่ม "เริ่มระบบ"** — ต้องกดปุ่มนี้ที่จอหลัก **1 ครั้งก่อนเริ่มงาน** เพื่อปลดล็อกการเล่นเสียงอัตโนมัติ เพราะเบราว์เซอร์จะบล็อกไม่ให้เล่นเสียงจากคำสั่งที่มาจากมือถือ (ไม่ใช่การคลิกโดยตรงบนจอหลัก) จนกว่าจะมีการคลิกบนจอหลักอย่างน้อยหนึ่งครั้ง หลังจากกดแล้วเพื่อนๆ เพิ่มเพลงจากมือถือได้ตามปกติตลอดงาน — ระบบจำไว้ว่ากดแล้ว **ถาวรบนอุปกรณ์/เบราว์เซอร์นั้น** (ใช้ localStorage ไม่ใช่แค่จำในแท็บเดียวหรือเซสชันเดียวอีกต่อไป) จึงไม่มีป๊อปอัพต้อนรับ/ปุ่มเริ่มระบบโผล่ขึ้นมาอีกเลย ไม่ว่าจะรีเฟรชหน้า เปิดแท็บใหม่ หรือปิด-เปิดเบราว์เซอร์ใหม่ก็ตาม จะกลับมาแสดงอีกครั้งก็ต่อเมื่อล้างข้อมูลเบราว์เซอร์ (เช่น Clear browsing data) หรือเปลี่ยนไปใช้อุปกรณ์/เบราว์เซอร์อื่นเท่านั้น
- **เพิ่ม STUN server สำรองหลายตัว** — ช่วยให้การเชื่อมต่อรีโมทหาทางเชื่อมต่อกันข้ามเครือข่ายที่แตกต่างกันได้ดีขึ้น (ดูหัวข้อ "การเชื่อมต่อรีโมทหลุดๆ ติดๆ" ด้านล่างสำหรับรายละเอียดและวิธีแก้เพิ่มเติมถ้ายังเจอปัญหา)
- **เชื่อมต่อใหม่ทันทีเมื่อเปิดจอมือถือกลับมา** — ปัญหาที่พบบ่อยที่สุดคือมือถือล็อกหน้าจอ/พักหน้าจอระหว่างงาน ทำให้การเชื่อมต่อ WebRTC หลุดแบบเงียบๆ โดยที่ระบบไม่รู้ตัวทันที ตอนนี้รีโมท (และจอหลัก) จะ**ตรวจสอบการเชื่อมต่อทันทีที่เปิดหน้าจอกลับมา** ถ้าพบว่าหลุดแล้วจะเชื่อมต่อใหม่ให้อัตโนมัติทันที โดยใช้รหัสห้อง/PIN/รหัสแอดมินที่จำไว้อยู่แล้ว **ไม่ต้องสแกน QR ใหม่**

## เริ่มงานใหม่ (ล้างคิว/คะแนน/ประวัติ)

ในเมนู **"⚙️ ตั้งค่า"** (จอหลัก) กดปุ่ม **"🔄 เริ่มงานใหม่"** เพื่อเคลียร์ข้อมูลของ "คืนนี้" ทั้งหมดในคราวเดียว ก่อนเริ่มงานครั้งใหม่:
- ล้างคิวเพลงปัจจุบัน (หยุดเล่นเพลงที่ค้างอยู่ด้วย)
- ล้างคะแนนร้องเพลงและกระดานผู้นำ
- ล้างประวัติเพลงที่เคยเล่น

**เพลย์ลิสต์ที่บันทึกไว้จะไม่ถูกลบ** เพราะเป็นของที่มักอยากเก็บไว้ใช้ซ้ำในงานครั้งต่อไป มีป๊อปอัพยืนยันก่อนล้างข้อมูลเสมอ กันการกดพลาด

## โหมดประหยัดพลัง

ในเมนู **"⚙️ ตั้งค่า"** (จอหลัก) มีสวิตช์ **"🔋 โหมดประหยัดพลัง"** ปิดอนิเมชัน screensaver ทั้งหมด (สปอตไลท์ส่าย, ไฟดิสโก้, โลโก้ลอย) เหลือแค่พื้นหลังนิ่งๆ — มีไว้สำหรับกรณีจอหลักเป็นอุปกรณ์ที่สเปกไม่แรงมาก (เช่นกล่องแอนดรอยราคาประหยัด) แล้วอนิเมชันเคลื่อนไหวเยอะๆ ทำให้เครื่องหน่วง/กระตุก เปิดโหมดนี้เพื่อลดภาระการประมวลผลกราฟิกลง ไม่กระทบฟังก์ชันการเล่นเพลงใดๆ

## จัดการอุปกรณ์ที่เชื่อมต่ออยู่

ในหน้าต่าง "📱 รีโมทมือถือ" (จอหลัก) เหนือ QR Code จะมีรายชื่ออุปกรณ์ที่เชื่อมต่ออยู่ทั้งหมด (พร้อมไอคอนบอกว่าเป็น 👑 แอดมิน หรือ 👤 ผู้ใช้ทั่วไป และชื่อเล่นที่ตั้งไว้) แต่ละแถวมีปุ่ม **"ตัดการเชื่อมต่อ"** ให้แอดมินตัดสิทธิ์อุปกรณ์นั้นออกจากห้องได้ทันที มีประโยชน์เมื่อ:
- มีคนที่ไม่ควรมีสิทธิ์เชื่อมต่ออยู่ (กรณีลืมล็อก PIN)
- อุปกรณ์ค้างสถานะแปลกๆ จากปัญหาการเชื่อมต่อ ไม่ต้องรอให้หลุดเอง

## จำการเชื่อมต่อไว้ ต่อได้เองหลังพักหน้าจอ/ปิดจอ (รีโมท + จอที่ 2)

เมื่อหน้าจอมือถือ/จอที่ 2 พักหน้าจอหรือล็อกจอไว้สักพัก เบราว์เซอร์มักจะ**พักหรือเลิกใช้งานแท็บที่เปิดค้างไว้เพื่อประหยัดแบตเตอรี** ซึ่งอาจทำให้การเชื่อมต่อกับจอหลักหลุดไปเงียบๆ โดยไม่มีสัญญาณเตือนใดๆ ระบบมีการป้องกันไว้หลายชั้นเพื่อให้กลับมาเชื่อมต่อเองได้ทันทีโดยไม่ต้องสแกน QR ใหม่:

- **จำรหัสห้อง/PIN/รหัสแอดมันไว้แบบถาวร** (localStorage) ไม่ใช่แค่จำในเซสชันเดียวเหมือนเดิมอีกต่อไป — แม้เบราว์เซอร์จะปิดแท็บทิ้งไปจริงๆ เพื่อประหยัดหน่วยความจำ พอเปิดกลับมาก็ยังจำได้และเชื่อมต่อให้เองอัตโนมัติ
- **ตรวจสอบทันทีที่กลับมาเปิดหน้าจอ** ผ่าน 2 เหตุการณ์คู่กัน (`visibilitychange` และ `focus`) เผื่อกรณีเบราว์เซอร์บางตัวไม่แจ้งเหตุการณ์ใดเหตุการณ์หนึ่งอย่างถูกต้อง
- **ตรวจสอบเป็นระยะทุก 10 วินาทีเป็นตาข่ายนิรภัยชั้นสุดท้าย** ไม่ต้องพึ่งเหตุการณ์ของเบราว์เซอร์เลยแม้แต่น้อย รับประกันว่าการเชื่อมต่อที่หลุดจะไม่ค้างเกิน ~10 วินาทีโดยไม่มีการพยายามเชื่อมต่อใหม่

ทั้งหมดนี้ใช้ได้กับทั้งรีโมทผู้ใช้ทั่วไป รีโมทแอดมิน และจอที่ 2 เหมือนกันทุกจุด

## การเชื่อมต่อรีโมทหลุดๆ ติดๆ ไม่เสถียร

ถ้ายังเจอปัญหาเชื่อมต่อไม่เสถียรหลังอัปเดตเวอร์ชันนี้ (ซึ่งเพิ่ม STUN server สำรองให้แล้ว) สาเหตุที่เป็นไปได้และวิธีแก้เรียงตามความเป็นไปได้:

1. **ไม่ได้เปิดผ่าน HTTPS** — เป็นสาเหตุอันดับ 1 ที่พบบ่อยที่สุด WebRTC (ที่ใช้เชื่อมต่อรีโมท) ทำงานไม่เสถียรมากบน HTTP ธรรมดา ต้องเปิดผ่าน HTTPS จริง (เช่น GitHub Pages) หรือ `localhost` เท่านั้น — ดูหัวข้อ "แนะนำวิธีการนำโปรเจกต์อัปโหลดไปยัง GitHub Pages" ในบทสนทนาก่อนหน้า หรือแบนเนอร์เตือนสีเหลืองที่ขึ้นบนจอถ้ายังเปิดผ่าน HTTP อยู่
2. **เครือข่ายที่มี NAT/Firewall เข้มงวด** (Wi-Fi โรงแรม, Wi-Fi ออฟฟิศ, มือถือบางเครือข่าย) — STUN server ที่เพิ่มให้แล้วช่วยได้ระดับหนึ่ง แต่เครือข่ายที่เข้มงวดมากบางกรณีต้องมี **TURN server** (relay การเชื่อมต่อ) ถึงจะทะลุผ่านได้ ซึ่งเป็นบริการที่ต้องสมัครสมาชิก (มีแพ็กเกจฟรีจากผู้ให้บริการอย่าง metered.ca, Twilio, Xirsys) แล้วนำ URL/username/credential มาใส่ในไฟล์ `app.js` และ `remote.js` ที่ตัวแปร `ICE_CONFIG` — มีคอมเมนต์กำกับไว้ในโค้ดทั้งสองไฟล์แล้วว่าต้องเพิ่มบรรทัดแบบไหน (`{ urls: 'turn:YOUR_TURN_HOST:3478', username: 'YOUR_USERNAME', credential: 'YOUR_CREDENTIAL' }`)
3. **เปิดหน้ารีโมทค้างไว้หลายแท็บ/หลายเครื่องพร้อมกันมากเกินไป** — จอหลักต้อง broadcast สถานะให้ทุกการเชื่อมต่อพร้อมกัน ถ้ามือถือหลายสิบเครื่องเชื่อมพร้อมกันอาจทำให้จอหลัก (ถ้าเป็นมือถือ/กล่องแอนดรอยที่แรงไม่มาก) หน่วงได้ ลองทดสอบกับจำนวนเครื่องน้อยลงเพื่อดูว่าอาการดีขึ้นหรือไม่
4. **Broker กลางของ PeerJS (0.peerjs.com) เป็นบริการฟรีสาธารณะ** ไม่มี SLA รับประกันความเสถียร ถ้าอาการยังไม่ดีขึ้นหลังลองข้อ 1-3 แล้ว ทางเลือกสุดท้ายคือการรันเซิร์ฟเวอร์ PeerServer ของตัวเอง (`npm install peer` แล้วตั้งค่า custom host/port ใน `new Peer()`) ซึ่งเป็นการเปลี่ยนสถาปัตยกรรมที่ใหญ่ขึ้น — แจ้งมาได้ถ้าต้องการให้ช่วยตั้งค่าส่วนนี้เพิ่มเติม

## ถ้าเชื่อมต่อ YouTube ไม่สำเร็จ

บางครั้งสคริปต์ของ YouTube (โหลดจาก youtube.com) อาจโหลดไม่สำเร็จหรือช้าผิดปกติ — สาเหตุมักมาจากอินเทอร์เน็ตขาดๆ หายๆ, ไฟร์วอลล์/เครือข่ายบล็อก youtube.com, หรือตัวบล็อกโฆษณาบล็อกสคริปต์นี้ไปด้วย ซึ่งเป็นปัญหาที่อยู่นอกเหนือการควบคุมของเว็บนี้โดยตรง — ระบบมีการรับมือไว้ดังนี้:

- ถ้ากดเล่นเพลง YouTube แล้วเชื่อมต่อไม่สำเร็จ จะขึ้นข้อความแจ้งเตือน **"ยังเชื่อมต่อ YouTube ไม่สำเร็จ กำลังลองใหม่..."** และ**ลองเชื่อมต่อซ้ำให้อัตโนมัติทุก 1 วินาที นานสูงสุด 20 วินาที**
- ถ้าเชื่อมต่อสำเร็จระหว่างที่กำลังลองใหม่ เพลงจะเริ่มเล่นให้ทันทีพร้อมข้อความแจ้งว่าเชื่อมต่อสำเร็จแล้ว ไม่ต้องกดเล่นซ้ำเอง
- ถ้าครบ 20 วินาทีแล้วยังไม่สำเร็จ จะขึ้นข้อความแนะนำให้ตรวจสอบอินเทอร์เน็ต/ตัวบล็อกโฆษณา แล้วลองกดเล่นเพลงนั้นใหม่อีกครั้ง

## เรื่องโฆษณาก่อนเริ่มเพลง

**บล็อกโฆษณาที่ฝังมากับวิดีโอ YouTube จากภายในโค้ดของแอปนี้ไม่ได้ และไม่ควรทำครับ** ขออธิบายเหตุผลทางเทคนิค:

- วิดีโอเล่นผ่าน **YouTube IFrame Player API** อย่างเป็นทางการ ซึ่ง Google ไม่เปิดช่องให้เว็บภายนอกตรวจจับหรือข้ามโฆษณาได้เลย (ไม่มีคำสั่ง "ข้ามโฆษณา" ใน API)
- ตัว iframe ของ YouTube เป็นคนละ origin กับเว็บเรา เบราว์เซอร์บล็อกไม่ให้เว็บเราเข้าไปยุ่งกับเนื้อหาภายใน iframe ได้ (เพื่อความปลอดภัยของผู้ใช้ทุกเว็บไซต์ ไม่ใช่แค่เว็บนี้) จึงไม่มีทาง "คลิกข้ามโฆษณา" จากโค้ดของเราได้จริงๆ
- การพยายามหาวิธีเลี่ยง/แฮ็กรอบข้อจำกัดนี้ อาจผิดข้อกำหนดการใช้งาน (Terms of Service) ของ YouTube สำหรับ IFrame API ซึ่งเสี่ยงทำให้โดเมนที่ใช้ฝังวิดีโอถูกจำกัดสิทธิ์การเข้าถึงได้

**วิธีที่ใช้ได้จริงและถูกต้องตามนโยบาย:**
1. **ติดตั้งส่วนขยายบล็อกโฆษณา** (เช่น uBlock Origin, AdGuard) บนเบราว์เซอร์ของอุปกรณ์ที่ใช้เป็นจอหลัก — บล็อกได้ที่ระดับเครือข่าย/เบราว์เซอร์ก่อนโฆษณาจะโหลด (จากที่เห็นใน error log ก่อนหน้านี้ เครื่องของคุณมีการบล็อกคำขอจาก `googleads.g.doubleclick.net` อยู่แล้วบางส่วน ซึ่งเป็นสัญญาณว่ามีตัวบล็อกโฆษณาทำงานอยู่บ้างแล้ว)
2. **ใช้บัญชี YouTube Premium** ล็อกอินบนเบราว์เซอร์ที่ใช้เปิดจอหลัก — วิธีนี้ปลอดโฆษณา 100% อย่างถูกต้องตามนโยบายของ YouTube เอง ไม่ต้องพึ่งเทคนิคใดๆ เพิ่มเติม
3. **หน้าจอ "กำลังเริ่มเล่น" คั่นระหว่างเปลี่ยนเพลง** (มีอยู่แล้วในแอปนี้) — ไม่ได้บล็อกโฆษณาจริงๆ แต่ปิดคลุมช่วงเปลี่ยนเพลงทั้งหมดด้วยภาพปกเพลงเบลอ+ชื่อเพลง+แอนิเมชันโหลด แล้วจางหายไปเองทันทีที่เพลงเริ่มเล่นจริง (ตรวจจับผ่านสถานะ "PLAYING" ของ Player) ไม่ว่าจะมีโฆษณาคั่นหรือไม่ก็ตาม ช่วยให้ดูเรียบร้อยเป็นมืออาชีพขึ้นระหว่างรอ แทนที่จะเห็นจอ YouTube เปล่าๆ หรือโฆษณาโผล่มาแบบดิบๆ — มีข้อความบอกตรงๆ ว่า "อาจมีโฆษณาคั่นบ้างเป็นบางครั้ง" ไม่ได้หลอกผู้ใช้ว่าไม่มีโฆษณาเลย ใช้ได้ทั้งจอหลักและจอที่ 2 (คนละ player แยกกัน จึงจางหายไม่พร้อมกันเป๊ะๆ ตามจังหวะการโหลดของแต่ละเครื่อง) มีระบบ timeout สำรอง 20 วินาทีกันจอค้างด้วย
   - **ปิดเสียงของ player จริงไว้ตลอดช่วงที่หน้าจอนี้แสดงอยู่ (เงียบสนิท ไม่มีเสียงใดๆ คลอ)** ทั้งจอหลักและจอที่ 2 เพื่อไม่ให้เสียงโฆษณาที่อาจคั่นอยู่มารบกวนระหว่างรอ แล้วคืนเสียงให้อัตโนมัติทันทีที่เพลงเริ่มเล่นจริง (หน่วงไว้ประมาณ 1.2 วินาทีหลังตรวจพบสถานะ "PLAYING" ก่อนคืนเสียงจริง เผื่อกรณี YouTube รายงานสถานะนี้ตั้งแต่โฆษณาเริ่มเล่นด้วย)
     ⚠️ **ข้อจำกัดที่ควรทราบ**: YouTube ไม่มีวิธีให้เว็บภายนอกแยกแยะได้แน่นอน 100% ว่าขณะนั้นกำลังเล่น "โฆษณา" หรือ "เพลงจริง" อยู่ (Player API ไม่เปิดเผยข้อมูลนี้) ระบบจึงใช้การหน่วงเวลาช่วยลดโอกาสที่เสียงโฆษณาจะหลุดออกมาได้ แต่**ไม่สามารถการันตีว่าจะไม่มีเสียงโฆษณาหลุดออกมาเลย 100% ในทุกกรณี** โดยเฉพาะเพลงที่มีโฆษณายาวกว่าปกติ

## ประวัติเพลงที่เล่นไปแล้ว

กดเมนู **"🔎 ค้นหาเพลง" → "🔥 ยอดนิยม"** บนจอหลักเพื่อดูรายการเพลงที่เล่นไปแล้วทั้งหมดในเซสชันนี้ (เรียงจากล่าสุดไปเก่าสุด) — ปุ่มนี้อยู่ในหน้าค้นหาโดยตั้งใจ เพื่อให้เห็นเพลงที่เพิ่งเล่นไปพร้อมๆ กับตอนกำลังหาเพลงใหม่ แต่ละรายการจะบอก:
- ใครเป็นคนเพิ่มเพลงนั้น (ถ้ามี)
- สาเหตุที่เปลี่ยนออกจากเพลงนั้น (เล่นจบ / ข้าม / ลบออกจากคิว / เปลี่ยนเพลย์ลิสต์ / เล่นไม่ได้)
- เวลาที่ผ่านมา (เช่น "5 นาทีที่แล้ว")

กด **"+ คิว"** ที่รายการประวัติเพื่อนำเพลงนั้นกลับมาเพิ่มเข้าคิวอีกครั้งได้ทันที และมีปุ่ม **"ล้างประวัติ"** ถ้าต้องการเริ่มใหม่

ระบบยังใช้ประวัตินี้เตือนอัตโนมัติด้วย — ถ้าค้นหา/เพิ่มเพลงที่เพิ่งเล่นไปในช่วง 15 เพลงล่าสุด หรือเพลงที่มีอยู่ในคิวแล้ว จะมี toast แจ้งเตือนขึ้นมา (แต่ยังคงเพิ่มเข้าคิวให้ตามปกติ ไม่ได้บล็อก)

ประวัติจะถูกบันทึกไว้ใน `localStorage` ของเบราว์เซอร์เครื่องที่เป็นจอหลัก (คงอยู่แม้ปิดแท็บ/รีสตาร์ทเบราว์เซอร์ จนกว่าจะกดล้างประวัติเอง)

## ล็อกห้องด้วยรหัส PIN

ค่าเริ่มต้นคือ **ไม่ล็อก** — ใครก็ตามที่มีลิงก์/QR หรือรหัสห้องจะเข้าคุมคิวได้ทันที ถ้าต้องการกันคนแปลกหน้าเข้ามาป่วนคิว (เช่น ใช้ในงานเปิด หรือ Wi-Fi สาธารณะที่คนนอกอาจดักลิงก์ได้) ให้เปิดใช้งานได้จากปุ่ม "📱 รีโมทมือถือ" บนจอหลัก:

1. ติ๊กช่อง **"ล็อกห้องด้วยรหัส PIN"** — ระบบจะสุ่มรหัส PIN 4 หลักให้อัตโนมัติ (ใช้กับ **รีโมทผู้ใช้ทั่วไป** เท่านั้น — รีโมทแอดมินไม่ต้องพึ่ง PIN นี้ ดูหัวข้อถัดไป)
2. QR Code จะฝัง PIN ไว้ในลิงก์ให้แล้ว — คนที่ **สแกน QR โดยตรง** จะเข้าห้องได้เลยโดยไม่ต้องพิมพ์ PIN เอง
3. คนที่ได้ **รหัสห้องแบบพิมพ์เอง** (ไม่ได้สแกน QR) จะต้องกรอกรหัส PIN ในช่อง "รหัส PIN" ที่หน้ารีโมทด้วย ถ้าใส่ผิดจะขึ้นข้อความแจ้งเตือนและไม่ได้เข้าห้อง
4. กด **"สุ่มใหม่"** เพื่อเปลี่ยนรหัส PIN ได้ทุกเมื่อ (อุปกรณ์ที่เชื่อมต่ออยู่แล้วก่อนหน้าจะไม่หลุด — ใช้ตรวจสอบเฉพาะตอนเชื่อมต่อครั้งแรกเท่านั้น)
5. ปิดล็อกได้ตลอดเวลาโดยติ๊กออกจากช่องเดิม

รหัส PIN จะคงอยู่ตลอด session ของแท็บจอหลัก (เหมือนรหัสห้อง) และรีเซ็ตใหม่เมื่อปิดแท็บ/เปิดแอปใหม่

## รีโมทแอดมิน vs รีโมทผู้ใช้ทั่วไป (QR แยกกัน)

ปุ่ม "📱 รีโมทมือถือ" บนจอหลักตอนนี้แสดง **QR สองชุดแยกกัน**:

| | 👤 รีโมทผู้ใช้ทั่วไป | 👑 รีโมทแอดมิน |
|---|---|---|
| ค้นหา/เพิ่มเพลง | ✅ | ✅ |
| ลบ/ยกเลิกเพลงของตัวเอง | ✅ | ✅ |
| ปรับจังหวะ (Tempo) | ✅ | ✅ |
| ปรับระดับเสียง / ปิดเสียง | ✅ | ✅ |
| เล่น/หยุด, ข้าม, ก่อนหน้า | ❌ | ✅ |
| จัดเรียงคิว / แทรกเล่นถัดไป | ❌ | ✅ |
| เปิดเพลย์ลิสต์จากรีโมท | ❌ | ✅ |
| ต้องมี PIN ห้อง (ถ้าเปิดใช้) | ต้องมี | ไม่ต้อง (มีรหัสแอดมินของตัวเองแทน) |

**วิธีใช้:** แจก QR "รีโมทผู้ใช้ทั่วไป" ให้เพื่อนทุกคนตามปกติ ส่วน QR/ลิงก์ "รีโมทแอดมิน" ให้แจกเฉพาะคนที่ไว้ใจให้ช่วยควบคุมเพลง (เช่น ผู้ช่วยงาน/เจ้าของงาน) เพราะสิทธิ์แอดมินควบคุมได้ทุกอย่างเหมือนนั่งอยู่ที่จอหลัก

- ลิงก์แอดมินมี **รหัสลับ (admin token)** ฝังอยู่ในตัวเอง แยกจากรหัส PIN ของผู้ใช้ทั่วไปโดยสิ้นเชิง ต่อให้ปิด/เปิด PIN ก็ไม่กระทบสิทธิ์แอดมิน
- กด **"สุ่มรหัสแอดมินใหม่ (ยกเลิก QR เดิม)"** เพื่อทำให้ QR/ลิงก์แอดมินชุดเก่าใช้ไม่ได้อีกต่อไป (คนที่เชื่อมต่ออยู่แล้วจะไม่ถูกตัดสิทธิ์ทันที แต่ลิงก์เดิมจะเชื่อมต่อใหม่ไม่ได้แล้ว)
- หน้ารีโมทที่เชื่อมต่อด้วยสิทธิ์แอดมินจะมีป้าย "👑 แอดมิน" และปุ่มควบคุมเพิ่มเติม (เล่น/หยุด/ข้าม/ก่อนหน้า, จัดเรียงคิว, เปิดเพลย์ลิสต์) ปรากฏขึ้นให้อัตโนมัติ
- การเปลี่ยนรหัส PIN/รหัสแอดมินเอง (ตั้งค่าความปลอดภัยของห้อง) ทำได้จากจอหลักเท่านั้น แม้แต่รีโมทแอดมินก็ไม่สามารถเปลี่ยนได้จากระยะไกล เพื่อป้องกันมือถือที่หลุดไปตกอยู่ในมือคนอื่นมาแก้ไขความปลอดภัยของห้อง
- **ต้องกรอก "ชื่อของคุณ" ก่อนเชื่อมต่อเสมอ** (บังคับ ไม่ว่าจะพิมพ์รหัสห้องเองหรือสแกน QR ก็ตาม) เพื่อให้รู้ว่าใครเพิ่ม/ลบเพลงไหนในคิวและประวัติ — ถ้าเบราว์เซอร์เครื่องนั้นเคยกรอกชื่อไว้แล้วจากการเชื่อมต่อครั้งก่อน จะจำชื่อเดิมไว้ให้และเชื่อมต่อผ่าน QR ได้ทันทีโดยไม่ต้องพิมพ์ซ้ำ

## API Key เริ่มต้นสำหรับค้นหาเพลง

ระบบมาพร้อม YouTube Data API Key เริ่มต้นให้แล้ว ใช้ค้นหาเพลงด้วยคำได้ทันทีโดยไม่ต้องตั้งค่าอะไรเพิ่ม สามารถเปลี่ยนเป็น API Key ของตัวเองได้ทุกเมื่อ — บนจอหลักไปที่เมนู **"⚙️ ตั้งค่า"** ส่วนบนรีโมทไปที่แท็บ "ตั้งค่า" — ค่าที่บันทึกเองจะมีผลเหนือค่าเริ่มต้นทันที

⚠️ **ข้อควรระวัง:** API Key ที่ฝังมาเป็นค่าเริ่มต้นนี้ปรากฏอยู่ในโค้ดที่ทุกคนเข้าถึงได้ (เพราะเป็นเว็บฝั่ง client ล้วน) หากมีคนนำ Key นี้ไปใช้เกินโควตา การค้นหาอาจหยุดทำงานชั่วคราว แนะนำให้ไปที่ [Google Cloud Console](https://console.cloud.google.com/) แล้ว **จำกัดสิทธิ์ของ Key** (API restrictions → เลือกเฉพาะ "YouTube Data API v3", และ/หรือ HTTP referrer restrictions ให้ใช้ได้เฉพาะโดเมนที่โฮสต์เว็บนี้) หรือสร้าง Key ใหม่ของตัวเองมาใส่แทนเพื่อความปลอดภัยและเสถียรภาพในระยะยาว

## เล่นเพลงจากไฟล์ในเครื่อง (นอกจาก YouTube)

นอกจากค้นหาจาก YouTube แล้ว ยังเพิ่มเพลงจาก**ไฟล์เพลงที่เก็บไว้ในเครื่องจอหลัก**ได้ด้วย เหมาะสำหรับเพลงที่หาใน YouTube ไม่เจอ หรือไม่อยากพึ่งอินเทอร์เน็ตตลอดงาน

### วิธีเชื่อมต่อโฟลเดอร์เพลง
1. จอหลัก ไปที่ **"⚙️ ตั้งค่า" → หัวข้อ "เพลงจากอุปกรณ์"**
2. กด **"📂 เลือกโฟลเดอร์เพลง"** แล้วเลือกโฟลเดอร์หลักที่เก็บไฟล์เพลงไว้ (เบราว์เซอร์จะขอสิทธิ์เข้าถึงโฟลเดอร์นั้น)
3. ระบบจะ**สแกนหาไฟล์เพลงในโฟลเดอร์ย่อยทั้งหมดโดยอัตโนมัติ** ไม่ว่าจะซ้อนกี่ชั้นก็ตาม (รองรับไฟล์เสียง `.mp3 .m4a .wav .ogg .flac .aac .wma` และไฟล์วิดีโอ `.mp4 .m4v .webm .mov .avi .mkv .mpg .mpeg .dat .wmv` — **ไฟล์จะเล่นได้จริงหรือไม่ขึ้นกับว่าเบราว์เซอร์ถอดรหัสไฟล์นั้นได้ไหม:** Chrome/Edge เล่น `.mp4` และ `.mp3` ได้ดีที่สุด ส่วน `.mpg .mpeg .dat` (VCD) `.wmv` และ `.avi` บางไฟล์มักเล่นไม่ได้ ถ้าเล่นไม่ได้ระบบจะแจ้งเตือนและข้ามไปเพลงถัดไปให้เอง)
4. เสร็จแล้วจะเห็นจำนวนไฟล์ที่พบ พร้อมใช้ค้นหาได้ทันที

### การค้นหาที่แสดงทั้งสองแหล่ง
พิมพ์ค้นหาในหน้า "🔎 ค้นหาเพลง" ตามปกติ (ทั้งจอหลักและรีโมท) — ผลลัพธ์จะรวมทั้งจาก YouTube และไฟล์ในเครื่องเข้าด้วยกัน โดยมีป้ายบอกแหล่งที่มาให้แยกออกชัดเจน:
- 🌐 **YouTube** — เพลงจากการค้นหา YouTube Data API หรือลิงก์ที่วาง
- 💻 **อุปกรณ์** — เพลงจากไฟล์ในโฟลเดอร์ที่เชื่อมต่อไว้

ป้ายเดียวกันนี้จะโชว์ต่อเนื่องไปถึงรายการในคิวเพลงด้วย ให้รู้ตลอดว่าเพลงที่กำลังจะเล่นมาจากไหน

### ข้อจำกัดที่ต้องรู้ (สำคัญ)
- **ไฟล์เพลง/วิดีโอเล่นที่จอหลักเท่านั้น** — เพราะไฟล์อยู่ในเครื่องจอหลักจริงๆ ไม่ได้ส่งไปให้อุปกรณ์อื่น รีโมทและจอที่ 2 เห็นแค่ชื่อเพลง (เพิ่ม/ลบเข้าคิวได้ตามปกติ) — แต่ **"เสียง" ของไฟล์ส่งไปออกที่จอที่ 2 ได้** (ดูหัวข้อ "เรื่องเสียง" ด้านล่าง)
- **จอที่ 2 ไม่สามารถแสดงวิดีโอของเพลงจากไฟล์ในเครื่องได้** (เพราะไม่มีสิทธิ์เข้าถึงไฟล์นั้น) จะขึ้นข้อความ "กำลังเล่นจากอุปกรณ์ที่จอหลัก" แทนหน้าจอวิดีโอ — **ยกเว้นไฟล์ MP3 ที่มีเนื้อเพลงฝังอยู่** ซึ่งจอที่ 2 จะแสดงหน้าจอเนื้อเพลงแบบเดียวกับจอหลักได้ (ดูหัวข้อถัดไป)
- **ต้องเลือกโฟลเดอร์ใหม่ทุกครั้งที่รีเฟรชหน้าจอหลัก** เป็นข้อจำกัดด้านความปลอดภัยของเบราว์เซอร์เอง (ไม่อนุญาตให้เว็บไซต์จดจำสิทธิ์เข้าถึงไฟล์ข้ามเซสชันแบบเงียบๆ) — ถ้าเพลย์ลิสต์/ประวัติมีเพลงจากไฟล์ในเครื่องอยู่ ต้องเลือกโฟลเดอร์เดิมกลับมาใหม่ก่อน ระบบถึงจะเชื่อมโยงไฟล์เดิมกลับมาเล่นได้ถูกต้อง (ใช้ชื่อไฟล์และตำแหน่งในโฟลเดอร์ในการจดจำ ถ้าย้าย/เปลี่ยนชื่อไฟล์จะเชื่อมโยงไม่ได้อีก)
- รองรับเบราว์เซอร์ที่รองรับการเลือกโฟลเดอร์ (`webkitdirectory`) เท่านั้น — **Chrome, Edge บนคอมพิวเตอร์ใช้งานได้ดีที่สุด** อุปกรณ์แอนดรอย/กล่องทีวีบางรุ่นอาจไม่รองรับหรือรองรับไม่เต็มที่

## เนื้อเพลงไล่สีทีละคำสำหรับไฟล์ MP3 (จอหลัก + จอที่ 2)

ไฟล์เพลง MP3 บางไฟล์ (ที่สร้างจากซอฟต์แวร์คาราโอเกะไทยบางประเภท) มี**เนื้อเพลงฝังอยู่ในตัวไฟล์เอง** พร้อมจังหวะเวลาแม่นระดับคำ — ระบบตรวจจับและอ่านข้อมูลนี้ให้อัตโนมัติ ไม่ต้องตั้งค่าอะไรเพิ่ม:

- เมื่อเล่นไฟล์เสียงล้วน (.mp3 .wav .m4a .aac .flac .oga .wma — ไม่ใช่ไฟล์วิดีโอ) ระบบจะเปลี่ยนเป็น**หน้าจอ "กำลังเล่นเพลง"** โดยอัตโนมัติแทนจอวิดีโอเปล่าๆ
- **แสดงข้อมูลเพลง 3 บรรทัด**:
  - **รหัสเพลง** — ชื่อไฟล์เสมอ (ถ้าตั้งชื่อไฟล์เป็นชื่อเพลงจริงอยู่แล้ว บรรทัดนี้ก็จะโชว์ชื่อนั้นไปเลย)
  - **ชื่อเพลง** — ชื่อจริงที่ถอดได้จากข้อมูลฝังในไฟล์ (แสดงเฉพาะตอนถอดรหัสสำเร็จ)
  - **นักร้อง** — ชื่อศิลปินที่ถอดได้จากข้อมูลฝังในไฟล์ (แสดงเฉพาะตอนถอดรหัสสำเร็จ)
- **ถ้าไฟล์มีเนื้อเพลงฝังอยู่**: แสดงเนื้อเพลงไล่สีทีละคำแบบคาราโอเกะคลาสสิก — **คำที่ร้องผ่านแล้ว = สีน้ำเงินขอบขาว, คำที่ยังไม่ถึง = สีขาวขอบดำ** ไล่สีเนียนตามจังหวะเป๊ะ ไม่กระตุก โชว์บรรทัดปัจจุบัน + บรรทัดถัดไปเลือนๆ ด้านล่าง
- **ถ้าไฟล์มีภาพปกอัลบั้มฝังอยู่ด้วย (ID3 Album Art)**: ใช้เป็นพื้นหลัง (เบลอ+มืดลงให้เนื้อเพลงอ่านง่าย) ถ้าไม่มีปกก็ใช้พื้นหลังธีมแอปแทน
- **ถ้าไฟล์ไม่มีเนื้อเพลงฝังมาเลย**: แสดงแค่พื้นหลัง + "รหัสเพลง" ไม่มีส่วนเนื้อเพลง/ชื่อเพลง/นักร้อง (ไม่ใช่ข้อผิดพลาด เป็นพฤติกรรมที่ตั้งใจไว้)
- **แถบความคืบหน้า + เลื่อนเวลาเล่นได้** (จอหลักเท่านั้น) — แสดงเวลาปัจจุบัน/เวลาทั้งหมด กดหรือลากบนแถบเพื่อข้ามไปยังช่วงเวลาที่ต้องการได้ทันที เหมือนเครื่องเล่นเพลงทั่วไป เนื้อเพลงจะไล่สีตามตำแหน่งใหม่ให้อัตโนมัติ
- **จอที่ 2 แสดงข้อมูลเพลง+เนื้อเพลงไล่คำแบบเดียวกันทุกประการ** ซิงก์เวลากับจอหลักโดยอัตโนมัติ แม้จอที่ 2 จะไม่มีไฟล์เสียงอยู่เลยก็ตาม (จอหลักส่งข้อมูล+ภาพปก+จังหวะเวลาไปให้ รวมถึงอัปเดตทันทีเมื่อมีการเลื่อนเวลาเล่นที่จอหลัก ไม่ต้องรอนานถึง 4 วินาที) — แถบความคืบหน้าไม่แสดงที่จอที่ 2 เพราะเป็นตัวควบคุมของจอหลักเท่านั้น

### รายละเอียดทางเทคนิค (สำหรับผู้ดูแลระบบ)
- การถอดรหัสทั้งหมดทำงาน**ในเบราว์เซอร์ล้วนๆ ไม่มีการส่งไฟล์เพลงขึ้นเซิร์ฟเวอร์ที่ไหนเลย**
- อ่านข้อมูลจาก ID3v2 tag ของไฟล์ (frame `TEXT` สำหรับเนื้อเพลง, `APIC` สำหรับภาพปก) — รองรับทั้ง ID3v2.3 และ ID3v2.4
- **ค้นหาข้อมูลเนื้อเพลงด้วยลายเซ็นเฉพาะ ("LyrHdr1") โดยตรง แทนที่จะพึ่งค่าตัวเลขขนาด frame ที่ระบุไว้ในไฟล์** เพราะพบว่าไฟล์จากซอฟต์แวร์คาราโอเกะบางตัวเขียนค่าตัวเลขนี้ไม่ตรงตามมาตรฐาน (ไม่สม่ำเสมอกันในแต่ละไฟล์ด้วย) วิธีนี้จึงเชื่อถือได้มากกว่าและใช้ได้กับไฟล์ที่มีปัญหาลักษณะนี้โดยไม่ต้องตั้งค่าอะไรเพิ่ม
- ต้องใช้เบราว์เซอร์ที่รองรับ `DecompressionStream` (Chrome 80+, Edge 80+, Firefox 113+, Safari 16.4+) สำหรับคลายการบีบอัดเนื้อเพลง — เบราว์เซอร์รุ่นเก่ากว่านี้จะข้ามส่วนเนื้อเพลงไปเงียบๆ (ไม่ error) และแสดงแค่พื้นหลัง+ชื่อเพลงแทน
- **ไม่ใช่ไฟล์ MP3 ทุกไฟล์จะมีเนื้อเพลงแบบนี้** ขึ้นอยู่กับซอฟต์แวร์ที่ใช้สร้างไฟล์ — ถ้าไฟล์ของคุณไม่ได้มาจากซอฟต์แวร์คาราโอเกะไทยที่ใช้รูปแบบนี้โดยเฉพาะ ระบบจะตรวจไม่พบและแสดงแค่พื้นหลัง+ชื่อเพลงตามปกติ (ไม่ใช่บั๊ก)
- ข้อมูลที่ถอดรหัสแล้วจะถูก**เก็บ cache ไว้ในเซสชันนั้น** ไม่ต้องแกะไฟล์ซ้ำทุกครั้งที่เล่นเพลงเดิม (แต่จะถอดใหม่ถ้าเลือกโฟลเดอร์เพลงใหม่)

## หน้าจอหลัก — วิดีโอเต็มจอ + แถบลอยทับด้านบน

หน้าจอหลักออกแบบใหม่ให้ **วิดีโอและพื้นหลัง (ไฟดิสโก้ตอนไม่มีเพลงเล่น) ขยายเต็มหน้าจอเสมอ** — เมนู Header, แผงคิวเพลง, และแผงเสียงเอฟเฟกต์ เป็น **แถบลอยทับอยู่บนวิดีโอ** (พื้นหลังโปร่งใส 28% + เบลอเล็กน้อยให้อ่านง่าย) ในตำแหน่งเดิมทุกจุด (Header อยู่บน, คิวเพลงอยู่ขวา, เอฟเฟกต์อยู่ซ้าย) แทนที่จะแบ่งพื้นที่จอถาวรแบบเดิม

**ข้อดีของการเปลี่ยนแปลงนี้:**
- วิดีโอมีพื้นที่แสดงผลเต็มจอเสมอ ไม่ถูกบีบให้แคบลงจากการมีแผงคิว/เอฟเฟกต์เปิดอยู่
- **ซ่อนแถบไหนก็ตาม จะกดวิดีโอ/ปุ่มควบคุมของ YouTube ตรงจุดนั้นได้ปกติทันที** เพราะไม่มีอะไรมาบังการคลิกอีกต่อไป

**ปุ่มลอยซ่อน/แสดงคิวเพลง:** กดปุ่มวงกลม **▶/◀** ที่ขอบขวาของจอ (ตรงรอยต่อกับแผงคิวเพลง) เพื่อซ่อน/แสดง — **บนจอแนวตั้ง (มือถือ) ปุ่มจะเปลี่ยนเป็น ▼/▲ อัตโนมัติและย้ายไปอยู่ขอบล่างแทน** เพราะคิวเพลงจะกลายเป็นแถบลอยด้านล่างจอในแนวตั้งแทนแถบขวา (เหมาะกับหน้าจอแคบกว่า) ไม่กระทบข้อมูลคิวเพลงใดๆ ไม่ว่าจะซ่อนหรือแสดง

**⚠️ ข้อควรทราบ**: เนื่องจากตอนนี้ทุกแถบเป็นแบบ "ลอยทับ" หากเปิดแผงคิวเพลง/เอฟเฟกต์พร้อมกับที่มีแถบคอร์ดหรือชื่อเพลงวิ่งแสดงอยู่ บางส่วนของแถบเหล่านั้นอาจถูกแผงที่ลอยทับอยู่บังบางส่วน (เพราะพื้นหลังของแผงคิว/เอฟเฟกต์เป็นสีทึบพอสมควรแม้จะโปร่งใส 28% ก็ตาม) ถือเป็นลักษณะธรรมชาติของดีไซน์แบบลอยทับ ไม่ใช่ข้อผิดพลาด

## ชื่อเพลงที่กำลังเล่น (ตัวอักษรวิ่งทับมุมล่างของวิดีโอ)

ชื่อเพลงที่กำลังเล่นอยู่ตอนนี้ แสดงเป็น**ตัวอักษรวิ่ง (marquee)** ทับอยู่บริเวณด้านล่างของจอวิดีโอ — **พื้นหลังโปร่งใสทั้งหมด** ไม่มีแถบสีทับ จึงไม่บดบังวิดีโอที่กำลังเล่นอยู่

- ตัวอักษรวิ่ง**จากขวามือไปซ้ายมือ**ต่อเนื่องตลอดเวลาที่มีเพลงเล่นอยู่ (ไม่ใช่แค่ตอนชื่อยาวเกินพื้นที่เหมือนเวอร์ชันก่อนหน้า)
- ตัวหนังสือสีขาวมีเงาเข้มรอบตัวอักษร ช่วยให้อ่านออกชัดเจนไม่ว่าพื้นหลังวิดีโอตรงนั้นจะสว่างหรือมืด
- ความเร็วในการวิ่งปรับตามความยาวของข้อความอัตโนมัติ ข้อความยาวจะวิ่งช้าลงเล็กน้อยให้อ่านทันเท่าๆ กัน เริ่มต้นใหม่จากขวาสุดทุกครั้งที่เปลี่ยนเพลง
- แตะที่แถบนี้ได้เหมือนแตะวิดีโอทั่วไป เพื่อซ่อน/แสดงเมนูด้านบน (ฟีเจอร์ "แตะจอซ่อนเมนู" ที่มีอยู่แล้ว)

## โหมดเต็มจอของแอป + ซ่อน/แสดงเมนูด้วยการแตะจอ (จอหลัก)

- **Header ลอยทับด้านบนวิดีโอเสมอ** (พื้นหลังโปร่งใส 28% + เบลอ) ไม่กินพื้นที่แบ่งจอแบบเดิมอีกต่อไป — วิดีโอขยายเต็มจอได้เต็มที่โดยไม่ต้องพึ่งโหมดเต็มจอก็ได้
- ปุ่ม **"⛶ เต็มจอ"** ที่ header ใช้ Fullscreen API ของเบราว์เซอร์ขยาย**ทั้งหน้าแอป** ให้เต็มจอไปพร้อมกัน — คนละแบบกับปุ่มเต็มจอของตัว YouTube player เอง (ซึ่งจะขยายแค่กรอบวิดีโอ ไม่รวม UI ของแอป) กดซ้ำหรือกด Esc เพื่อย่อกลับ
- **ปุ่มลอยทรงกลมขนาดเล็ก ▲/▼** (โปร่งใส 40% ไม่บังจอ) ใต้ header กดเพื่อซ่อน/แสดงแถบเมนูด้านบนได้ตลอดเวลา เหมาะเวลาต้องการให้วิดีโอเต็มพื้นที่จอมากขึ้นโดยไม่ต้องออกจากโหมดเต็มจอ
- **แตะบนตัววิดีโอ YouTube เองใช้ควบคุมปุ่มต่างๆ ของ YouTube ได้ตามปกติเสมอ** (เล่น/หยุด, แถบเลื่อนเวลา, CC บรรยาย, ⚙️ ตั้งค่าของ YouTube) — จะไม่ไปสั่งซ่อน/แสดงเมนูของเราปนกันอีกต่อไป เพื่อไม่ให้ไปบังปุ่มเหล่านี้ การซ่อน/แสดงเมนูจึงใช้วิธีอื่นแทน:
  - **ปุ่มลอย ▲/▼ ใต้ header** เป็นวิธีหลักที่ใช้ได้แน่นอนทุกครั้ง ไม่ว่ากรณีใด
  - **แตะพื้นที่ว่างตอนยังไม่มีเพลงเล่น** (หน้าจอต้อนรับ/screensaver) ก็ซ่อน/แสดงเมนูได้เช่นกัน เพราะช่วงนั้นไม่มีปุ่ม YouTube ให้ชนกัน

## ลำดับเมนู Header (จอหลัก)

ปุ่มใน header เรียงจากซ้ายไปขวาตามลำดับนี้เสมอ: **🔎 ค้นหาเพลง → 📱 รีโมทมือถือ → 🎸 คอร์ด (ซ่อนอยู่โดยค่าเริ่มต้น — ดูหัวข้อ "คอร์ดเพลงแบบเรียลไทม์") → 🎚️ ช่องเสียง (โผล่เฉพาะตอนเล่นไฟล์ในเครื่อง — ดูหัวข้อ "ช่องเสียง Stereo / L+L / R+R") → 😀 อิโมจิ → ⚙️ ตั้งค่า → ⛶ เต็มจอ → 🚪 ออกจากระบบ** ทั้งหมดชิดขวาของจอเสมอ — บนจอแคบ/มือถือที่แสดงปุ่มไม่หมด ปัดนิ้ว (หรือลากด้วยเมาส์/เลื่อนล้อเมาส์) จากขวาไปซ้ายบนแถบเมนูเพื่อดูปุ่มที่เหลือได้ (รายละเอียดอยู่ในหัวข้อ "เมนู header บนมือถือจอเล็ก" ด้านล่าง)

ปุ่มซ่อน/แสดงคิวเพลงย้ายออกจาก header ไปเป็นปุ่มวงกลมลอยที่ขอบจอวิดีโอแทน (ดูหัวข้อ "ซ่อน/แสดงคิวเพลง" ด้านล่าง)

## คอร์ดเพลงแบบเรียลไทม์ (จอหลัก + จอที่ 2)

**ปุ่ม "🎸 คอร์ด" ที่ header ซ่อนอยู่โดยค่าเริ่มต้น** เปิดให้แสดงได้ที่ "⚙️ ตั้งค่า" → หัวข้อ "เมนู Header" → เปิดสวิตช์ "🎸 ปุ่มคอร์ด" (เหมาะสำหรับงานที่ไม่ได้ใช้ฟีเจอร์นี้ จะได้ไม่รกเมนู)

กดปุ่ม **"🎸 คอร์ด"** ที่ header เพื่อเปิดหน้าต่างเพิ่ม/แก้ไขคอร์ดของเพลงที่กำลังเล่นอยู่ (หรือเลือกจากคลังคอร์ดด้านล่างของหน้าต่างเพื่อแก้ไขเพลงอื่นได้แม้ไม่ได้เล่นอยู่ตอนนั้น) — ใช้ได้กับเพลงจาก **ทั้ง YouTube และไฟล์ในเครื่อง**

**2 โหมดการพิมพ์คอร์ด:**
- **โหมดง่าย** — พิมพ์คอร์ดเรียงลำดับ คั่นด้วยช่องว่าง เช่น `C G Am F C G F G` พร้อมกำหนด "วินาทีต่อคอร์ด" ระบบแบ่งเวลาให้เท่าๆ กันเอง
- **โหมดละเอียด** — พิมพ์เวลา (นาที:วินาที) ตามด้วยคอร์ด บรรทัดละ 1 คอร์ด เช่น `0:00 C` `0:04 G` `0:08 Am` ให้คอร์ดเปลี่ยนตรงจังหวะเพลงจริง

บันทึกแล้วคอร์ดจะขึ้นเป็น **แถบทับด้านบนของจอวิดีโอ** (พื้นหลังโปร่งใสสนิท ไม่มีแถบสีบังวิดีโอเลย กว้างพอดีกับจอวิดีโอ ไม่ทับแผงคิว) ตัวอักษรคอร์ดมีขอบเข้มรอบตัวอักษรแทนพื้นหลัง เพื่อให้อ่านชัดเจนได้ไม่ว่าฉากหลังวิดีโอตรงนั้นจะสว่างหรือมืด แสดงคอร์ดทั้งเพลงเรียงเป็นแถบตามสัดส่วนเวลาจริง แล้วไฮไลต์คอร์ดที่กำลังเล่นอยู่ด้วยสีทองเด่นชัด (ตัวใหญ่ขึ้น + เรืองแสง) **เลื่อนไฮไลต์ไปตามตำแหน่งเพลงโดยอัตโนมัติ** — ถ้าเพลงอยู่ในช่วง 15 วินาทีสุดท้ายพร้อมกัน แถบ "ถัดไป" จะเลื่อนลงมาไม่ให้ทับกับแถบคอร์ด

ครั้งต่อไปที่เล่นเพลงเดิมซ้ำ คอร์ดจะขึ้นเองโดยไม่ต้องพิมพ์ใหม่ และ**ส่งไปแสดงที่จอที่ 2 ด้วยพร้อมกัน** (จอที่ 2 ใช้เวลาเล่นของตัวเองซิงก์ไฮไลต์ จึงอาจคลาดเคลื่อนเล็กน้อยตามธรรมชาติของการเล่นคนละเครื่อง เหมือนกับชื่อเพลงวิ่งและนับถอยหลังเพลงถัดไป)

**⚠️ ข้อจำกัด:** เป็นคอร์ดที่พิมพ์เตรียมไว้เอง ไม่ใช่การแกะจากเสียงเพลงอัตโนมัติ (เหตุผลทางเทคนิคเดียวกับที่ปรับคีย์เสียงไม่ได้) เก็บไว้ใน `localStorage` ของจอหลักเท่านั้น ไม่แสดงบนรีโมท (รีโมทไม่มีจอวิดีโอให้ทับอยู่แล้ว)

## ออกจากระบบ

ปุ่ม **"🚪 ออกจากระบบ"** ที่ header (ปุ่มขวาสุด) เปิด**หน้าต่างยืนยันแบบ popup** ของแอปเอง (ไม่ใช่กล่องเตือนของเบราว์เซอร์) — กดยืนยันแล้วระบบจะหยุดเล่นเพลง ตัดการเชื่อมต่อกับรีโมท/จอที่ 2 ทั้งหมดให้เรียบร้อยก่อน แล้วพยายามปิดแท็บให้อัตโนมัติ (ถ้าเบราว์เซอร์ไม่อนุญาตให้ปิดเอง จะขึ้นข้อความให้ปิดแท็บด้วยตนเอง)

## ระบบจอที่ 2 (Second Screen)

จอเสริมไร้สาย เหมาะสำหรับวางไว้ให้นักร้อง/ผู้ชมดูแยกจากจอหลัก (เช่น จอหลักตั้งไว้ให้คนคุมเพลงเห็นเมนู+คิว ส่วนจอที่ 2 เป็นทีวีอีกตัวหรือแท็บเล็ตที่ตั้งให้ทุกคนเห็นแต่จอเต็มๆ ไม่มีเมนูรก) — **จอหลัก (จอที่ 1) ไม่มีอะไรเปลี่ยนแปลง** ยังคงมีเมนู/คิว/การควบคุมครบเหมือนเดิมทุกอย่าง

### วิธีเปิดใช้งาน
1. จอหลัก ไปที่ **"⚙️ ตั้งค่า" → เปิดสวิตช์ "🖥️ เปิดใช้งานจอที่ 2"**
2. ป๊อปอัพ QR Code ของจอที่ 2 จะขึ้นให้ทันที **ไม่ต้องกดปุ่มเพิ่มเติมใดๆ** — แสดงทั้ง QR, รหัสห้อง (ตัวใหญ่อ่านง่าย), และรหัส PIN (ถ้าตั้งไว้)
3. เปิดเบราว์เซอร์บนอุปกรณ์/จอที่จะใช้เป็นจอที่ 2 แล้วสแกน QR นั้น (หรือไม่มีกล้อง/สแกนไม่ได้ก็เปิดหน้าจอที่ 2 เองแล้วพิมพ์รหัสห้อง+PIN ที่เห็นในป๊อปอัพได้เลย)
4. จอที่ 2 จะเชื่อมต่อและแสดงผลอัตโนมัติ — ไม่มีปุ่มควบคุมใดๆ ให้กด ปลอดภัยที่จะเปิดทิ้งไว้ทั้งงานได้เลย
5. ดู QR อีกครั้งทีหลังได้จากเมนู "📱 รีโมทมือถือ" เช่นกัน (แยกป๊อปอัพกันชัดเจน ไม่ปนกับ QR ของรีโมทผู้ใช้ทั่วไป/แอดมิน)

### สิ่งที่จอที่ 2 แสดง
- วิดีโอเพลงที่กำลังเล่นแบบเต็มจอ (โหลดวิดีโอเดียวกับจอหลักเอง เป็นคนละ player กัน)
- ชื่อเพลงที่กำลังเล่นวิ่งจากขวาไปซ้ายทับด้านล่างจอ **แบบเดียวกับจอหลักทุกประการ** (ขนาดตัวอักษร ความเร็ว และพื้นหลังโปร่งใสเหมือนกัน)
- **แถบคอร์ดเพลง** (ถ้าเพลงนั้นมีคอร์ดบันทึกไว้) ทับด้านบนจอวิดีโอ เลื่อนไฮไลต์ตามจังหวะเพลงเหมือนจอหลัก
- ชื่อเพลงถัดไป **แบบกระพริบ** ในช่วง 15 วินาทีสุดท้ายก่อนเพลงจบ (เหมือนจอหลัก)
- ป๊อปอัพคะแนนร้องเพลง + กระดานผู้นำ 5 อันดับ เหมือนที่ขึ้นบนจอหลักและรีโมททุกประการ
- **ตอนไม่มีเพลงในคิว** พื้นหลังเป็นไฟดิสโก้ชุดเดียวกับจอหลัก (สปอตไลท์ส่าย, ไฟกระพริบรอบขอบ) พร้อมโลโก้และข้อความ "ไม่มีเพลงในคิว...กรุณาเลือกเพลง" กระพริบตรงกลางจอ (โลโก้อยู่นิ่งตรงกลาง ไม่ได้ลอยไปมาเหมือนจอหลัก)

### เรื่องเสียง — เลือกได้ว่าจะให้ออกจากจอไหน

ค่าเริ่มต้น: **เสียงออกที่จอหลัก** จอที่ 2 ปิดเสียงไว้เพื่อไม่ให้ซ้อนกัน — แต่ถ้าอยากให้เสียงออกจากจอที่ 2 แทน (เช่น จอที่ 2 ต่อกับลำโพงที่เสียงดีกว่า) ไปที่ **"⚙️ ตั้งค่า" → หัวข้อ "จอที่ 2"** จะมีสวิตช์ **"🔊 เสียงออกที่จอไหน"** ให้เลือก **"จอหลัก"** หรือ **"จอที่ 2"**:
- ระบบจะสลับให้อัตโนมัติ — ปิดเสียงฝั่งที่ไม่ได้เลือกให้เอง กันเสียงซ้อนโดยไม่ต้องปรับอะไรเพิ่ม
- ปุ่มปรับเสียง/ปิดเสียงเดิม (ทั้งที่จอหลักและรีโมท) จะไปควบคุมเสียงของจอที่เลือกไว้โดยอัตโนมัติ ไม่ต้องมีปุ่มชุดที่สองแยกให้สับสน
- สลับไปมาได้ตลอดเวลาระหว่างงาน
- ถ้าปิดใช้งาน "จอที่ 2" ในตั้งค่า ระบบจะดึงเสียงกลับมาที่จอหลักให้อัตโนมัติเสมอ

**เพลงจาก YouTube** ใช้ได้ตามนี้ทันที ส่วน **เพลง/ไฟล์ในเครื่อง** (วิดีโอหรือ MP3) ก็เลือกให้เสียงออกจอที่ 2 ได้เช่นกัน แต่ทำงานต่างจาก YouTube:

- YouTube: จอที่ 2 โหลดวิดีโอเองและเล่นเสียงเอง
- ไฟล์ในเครื่อง: ไฟล์อยู่ที่จอหลักเครื่องเดียว จึงเป็น **การส่งเสียงสดจากจอหลักไปให้จอที่ 2** ผ่านเครือข่าย (WebRTC เหมือนโทรเสียงทางเดียว ส่งเป็นสเตอริโอ) ภาพวิดีโอยังเล่นที่จอหลักเท่านั้น จอที่ 2 ขึ้นข้อความ "กำลังเล่นจากอุปกรณ์ที่จอหลัก"
- **เสียงที่จอที่ 2 จะมาช้ากว่าภาพที่จอหลักเล็กน้อย** (ประมาณ 100-300 มิลลิวินาที ขึ้นกับ WiFi) ลดได้แต่กำจัดไม่ได้เพราะเป็นข้อจำกัดของการส่งเสียงผ่านเครือข่าย — ถ้ามีคนดูภาพที่จอหลักแต่ฟังเสียงจากจอที่ 2 จะเห็นปากกับเสียงเหลื่อมกันนิดหน่อย (ไฟล์วิดีโอที่ฝังเนื้อเพลงมาในภาพ จึงแก้ให้ตรงไม่ได้ แต่ถ้ามีเนื้อเพลง MP3 ดูหัวข้อถัดไป)
- **เนื้อเพลงไล่สี MP3 ปรับให้ตรงกับเสียงได้:** ที่ ⚙️ ตั้งค่า → จอที่ 2 มีตัวเลือก **"⏱️ ชดเชยเสียงจอที่ 2"** (ค่าเริ่มต้น 250 มิลลิวินาที) ตอนเสียงออกจอที่ 2 ระบบจะหน่วงการไฮไลต์เนื้อเพลงให้ช้าลงตามค่านี้ ทั้งที่จอหลักและจอที่ 2 เพื่อให้ตรงกับเสียงที่ได้ยินจริง — ถ้ายังเหลื่อม ปรับค่าขึ้น/ลงจนตรง
- ปุ่มปรับเสียง/ปิดเสียงควบคุมเสียงที่จอที่ 2 ได้ตามปกติ
- ถ้าจอที่ 2 ขึ้นแถบ **"🔊 แตะที่หน้าจอเพื่อเปิดเสียง"**: เบราว์เซอร์บล็อกการเล่นเสียงอัตโนมัติ (เกิดเมื่อเพิ่งเปิด/รีเฟรชหน้าจอที่ 2 โดยยังไม่ได้แตะหน้าจอเลย) แตะที่ไหนก็ได้ 1 ครั้งแล้วเสียงจะมา
- ถ้า WiFi ไม่เสถียร เสียงที่ส่งไปจอที่ 2 อาจสะดุด ต่างจากไฟล์ที่เล่นตรงในเครื่อง — ถ้าระบบส่งเสียงไปจอที่ 2 ไม่ได้ (เช่นเบราว์เซอร์ไม่อนุญาต) จะแจ้งเตือนและ **ดึงเสียงกลับมาที่จอหลักให้อัตโนมัติ** ไม่ปล่อยให้เงียบ
- ถ้าตั้งเสียงออกจอที่ 2 แล้วจอที่ 2 หลุดการเชื่อมต่อ เสียงจะเงียบจนกว่าจะต่อกลับมา (หรือสลับกลับมาที่จอหลักในตั้งค่า) เหมือนกรณี YouTube

### ช่องเสียง Stereo / L+L / R+R (ไฟล์ในเครื่อง)

แผ่น/ไฟล์คาราโอเกะจำนวนมากบันทึกเสียงแยกซ้าย-ขวา: **ช่องหนึ่งเป็นดนตรีล้วน อีกช่องเป็นดนตรีผสมเสียงร้อง** (พบได้ในไฟล์ `.mpg .dat .avi .wmv .mp4` ที่ริปจากแผ่น และ MP3 karaoke) ระบบมีปุ่ม **🎚️ ช่องเสียง** ให้เลือกว่าจะเอาเสียงจากช่องไหน:

| โหมด | ลำโพงซ้ายได้ยิน | ลำโพงขวาได้ยิน | ใช้เมื่อ |
|---|---|---|---|
| **Stereo** (ค่าเริ่มต้น) | ช่องซ้าย | ช่องขวา | ไฟล์ทั่วไป |
| **L+L** | ช่องซ้าย | ช่องซ้าย | ช่องซ้ายเป็นดนตรีล้วน (ตัดเสียงร้อง) |
| **R+R** | ช่องขวา | ช่องขวา | ช่องขวาเป็นดนตรีล้วน |

- **ทุกโหมดมีเสียงออกทั้งสองลำโพงเสมอ** — ไม่ใช่การปิดเสียงลำโพงข้างใดข้างหนึ่ง แค่เลือกว่าเสียงที่ออกมาจากช่องไหน (L+L ไม่มีเสียงของช่องขวาเหลือรั่วอยู่เลย)
- **ปุ่มอยู่ที่ไหน:** header จอหลัก (ระหว่างปุ่ม 🎸 คอร์ด และ 😀 อิโมจิ) และแถบ "กำลังเล่น" ของรีโมท — **โผล่เฉพาะตอนเพลงที่กำลังเล่นเป็นไฟล์ในเครื่อง** (เพลง YouTube ใช้ไม่ได้ เพราะเบราว์เซอร์ไม่ให้เข้าถึงเสียงจาก YouTube) กดทีละครั้งวน Stereo → L+L → R+R → Stereo **รีโมททั่วไปกดได้เหมือนปุ่มปรับเสียง** ทุกเครื่องเห็นโหมดตรงกัน
- โหมดที่เลือกจะค้างไว้ข้ามเพลงถัดไปในงานเดียวกัน (จำไว้จนกว่าจะปิดแท็บ/เบราว์เซอร์) — ถ้าเพลงถัดไปเป็นแผ่นที่ช่องกลับด้าน ให้กดสลับใหม่
- ไม่รู้ว่าแผ่นนี้ช่องไหนเป็นดนตรีล้วน? กดสลับฟังได้เลย ไม่มีกฎตายตัว (บางแผ่นซ้าย บางแผ่นขวา)
- **ไฟล์เสียงช่องเดียว (โมโน)** ฟังเหมือนกันทุกโหมด (ทั้งสองลำโพงเสียงเท่ากัน ไม่เงียบ)
- ใช้ร่วมกับ "เสียงออกจอที่ 2" ได้ โหมดช่องเสียงที่เลือกมีผลกับเสียงที่ส่งไปจอที่ 2 ด้วย

**เบื้องหลัง/ข้อควรรู้:** ถ้าเลือก Stereo และให้เสียงออกที่จอหลัก (ค่าเริ่มต้น) ระบบจะไม่แตะตัวเล่นไฟล์เลย เล่นแบบเดิม 100% ครั้งแรกที่เลือก L+L / R+R หรือส่งเสียงไปจอที่ 2 ระบบจึงจะเปิดวงจรเสียงขั้นสูงของเบราว์เซอร์ (Web Audio API) ซึ่งต้องมีการคลิก/แตะหน้าจอหลักมาก่อนอย่างน้อย 1 ครั้ง (ปกติทำไปแล้วตอนกด "เข้าสู่ระบบ/เริ่มระบบ") ถ้าเบราว์เซอร์ไม่อนุญาต ระบบแจ้งเตือนแล้วกลับเป็น Stereo / ดึงเสียงกลับจอหลักให้ โดย **เสียงไม่หาย** — และเมื่อวงจรเสียงถูกเปิดแล้วจะคงอยู่จนกว่าจะรีเฟรชหน้า (ข้อจำกัดของเบราว์เซอร์ ยกเลิกการเชื่อมต่อไม่ได้) ซึ่งไม่ส่งผลเสียอะไร นอกจากอาจมีหน่วงของเสียงเพิ่มระดับสิบมิลลิวินาที

### การซิงก์วิดีโอ
จอที่ 2 โหลดวิดีโอเดียวกันแยกจากจอหลัก (คนละ YouTube player) จอหลักจะส่งตำแหน่งเวลาปัจจุบันไปให้เป็นระยะๆ (ทุก ~4 วินาที) เพื่อปรับ sync ให้ใกล้เคียงกันที่สุด — อาจมีความคลาดเคลื่อนเล็กน้อย (ไม่กี่วินาที) จากความแตกต่างของการโหลด/บัฟเฟอร์แต่ละอุปกรณ์ ถือเป็นเรื่องปกติของการเล่นวิดีโอคนละเครื่องพร้อมกัน

### ความปลอดภัย
จอที่ 2 เชื่อมต่อแบบ "รีโมทผู้ใช้ทั่วไป" — ถ้าเปิดล็อกห้องด้วย PIN ไว้ จอที่ 2 ก็ต้องใส่ PIN เดียวกันถึงจะเข้าได้ แต่จอที่ 2 **ไม่มีสิทธิ์สั่งอะไรกลับไปที่จอหลักได้เลย** เป็นได้แค่ผู้รับข้อมูลมาแสดงผลเท่านั้น จึงปลอดภัยที่จะเปิดค้างไว้แม้ในที่สาธารณะ



แถบปุ่มเมนูด้านบน (ค้นหาเพลง, เพลย์ลิสต์, รีโมทมือถือ, ซ่อนคิว, เต็มจอ, ตั้งค่า) ตอนนี้เป็น **แถบเลื่อนแนวนอน** — บนจอที่แคบเกินกว่าจะแสดงปุ่มทั้งหมดพร้อมกัน (เช่น มือถือจอเล็ก) ให้ **ปัดนิ้วซ้าย-ขวาบนแถบเมนู** เพื่อเลื่อนไปดูปุ่มที่ถูกบังอยู่ได้ (บนคอมพิวเตอร์ใช้ล้อเมาส์เลื่อนแนวนอน หรือลากด้วยเมาส์ได้เช่นกัน) โลโก้ "Sri Karaoke" ทางซ้ายจะไม่ถูกเลื่อนหายไปด้วย เห็นตลอดเวลา

## รองรับหน้าจอแนวตั้งและแนวนอน

ระบบสลับเลย์เอาต์ตามการหมุนหน้าจอโดยอัตโนมัติผ่าน CSS มาตรฐาน (`orientation: portrait`/`landscape`) ซึ่งเบราว์เซอร์ทุกตัวรองรับอยู่แล้ว ไม่ว่าจะเป็นมือถือ แท็บเล็ต หรือกล่องแอนดรอย:
- **แนวตั้ง**: วิดีโออยู่ด้านบน คิวเพลงอยู่ด้านล่าง (เรียงซ้อนกัน)
- **แนวนอน**: วิดีโอกับคิวเพลงอยู่เคียงข้างกัน (เหมือนจอคอมพิวเตอร์/ทีวี)

หมุนจอเมื่อไหร่ เลย์เอาต์จะสลับให้เองทันทีโดยไม่ต้องรีเฟรชหน้า และปรับปรุงเพิ่มเติมสำหรับ **มือถือแนวนอนที่จอเตี้ยมากๆ** (เช่น หมุนมือถือเล่นแนวนอน) โดยลดขนาด header/แถบต่างๆ ให้บางลงอัตโนมัติ เพื่อเหลือพื้นที่ให้วิดีโอมากที่สุดบนจอที่มีความสูงจำกัด

## โลโก้/ไอคอนแอป

เปลี่ยนมาใช้โลโก้ "Sri Karaoke" ที่ให้มา ทั้งใน header ของจอหลักและรีโมท รวมถึงไอคอนแอป (PWA) ตอนติดตั้งลงมือถือ/ทีวี หากต้องการเปลี่ยนโลโก้อีกครั้งในอนาคต แค่แทนที่ไฟล์ `icons/icon-192.png` และ `icons/icon-512.png` ด้วยไฟล์ใหม่ (ขนาดเท่าเดิม) ระบบจะดึงไปใช้เองทั้งหมดโดยไม่ต้องแก้โค้ด

## ป๊อปอัพข้อมูลเว็บไซต์/ลิขสิทธิ์ (แสดงทุกครั้งที่เปิดหน้า)

ทั้งจอหลักและรีโมทจะแสดงป๊อปอัพข้อมูลเกี่ยวกับเว็บไซต์และคำชี้แจงเรื่องลิขสิทธิ์ทุกครั้งที่เปิด/รีเฟรชหน้า (ไม่มีการจดจำว่าเคยกดยอมรับแล้ว) มีปุ่มให้เลือก 3 ปุ่ม:

- **"ยกเลิก"** — ระบบจะพยายามปิดแท็บให้อัตโนมัติ (ใช้ได้เฉพาะกรณีที่เบราว์เซอร์อนุญาต) หากปิดไม่ได้จะเปลี่ยนหน้าจอเป็นข้อความแจ้งให้ปิดแท็บด้วยตนเอง และบล็อกการใช้งานหน้านั้นต่อไป
- **"คุณสมบัติ"** — สลับเนื้อหาในป๊อปอัพจาก "เกี่ยวกับเว็บไซต์/ลิขสิทธิ์" ไปเป็น **รายละเอียดความสามารถและฟีเจอร์ทั้งหมดที่ระบบรองรับ** (แบ่งหมวดตามการค้นหาเพลง, การจัดการคิว, รีโมทมือถือ, การควบคุมการเล่น, และความสะดวกในการใช้งาน) กดซ้ำเพื่อสลับกลับไปดูข้อมูลเว็บไซต์เดิมได้
- **"📖 คู่มือการใช้งาน"** — เปิดคู่มือการใช้งานฉบับเต็ม (หน้า `manual.html`) ในแท็บใหม่ อ่านง่าย มีสารบัญ ใช้ออฟไลน์ได้ หน้านี้สร้างจากไฟล์ `คู่มือการใช้งาน.md` — **ถ้าแก้ไฟล์ .md ต้องสร้าง `manual.html` ใหม่** ด้วยคำสั่ง `python3 tools/build-manual.py` (ต้องติดตั้ง `pip install markdown` ก่อน)
- **"เข้าสู่ระบบ"** — ปิดป๊อปอัพแล้วเข้าใช้งานตามปกติ (ใช้ได้จากทั้งสองมุมมอง ไม่ต้องสลับกลับไปหน้าแรกก่อน) — **บนจอหลักเท่านั้น** จะมีเมนูเลือกโหมดการแสดงผลโผล่ตามมาอีกขั้น (ดูหัวขัดถัดไป)

ต้องการแก้ไขข้อความในป๊อปอัพนี้ ให้แก้ไขได้ตรงๆ ในไฟล์ `index.html` และ `remote.html` ที่ส่วน `<div class="disclaimer-overlay" id="disclaimer-modal">` — เนื้อหาข้อมูลเว็บไซต์อยู่ใน `#disclaimer-panel-about` ส่วนเนื้อหาคุณสมบัติอยู่ใน `#disclaimer-panel-features`

## เลือกโหมดการแสดงผล (จอหลัก, หลังกด "เข้าสู่ระบบ")

เปิด `index.html` แล้วกด "เข้าสู่ระบบ" จะมีเมนูให้เลือกว่าอุปกรณ์นี้จะทำหน้าที่อะไร โดยไม่ต้องรู้ล่วงหน้าว่าต้องเปิดไฟล์ไหน:

- **🖥️ จอหลัก** — ปิดเมนูแล้วใช้งานอุปกรณ์นี้เป็นจอหลักตามปกติ (พฤติกรรมเดิม)
- **📺 จอที่ 2** — เปลี่ยนไปเปิด `screen2.html` ให้อัตโนมัติ
- **📱 รีโมท** — เปลี่ยนไปเปิด `remote.html` ให้อัตโนมัติ

มีประโยชน์เวลาแจกลิงก์ `index.html` เพียงลิงก์เดียวให้ทีมงาน แล้วให้แต่ละคนเลือกเองหน้างานว่าอุปกรณ์ของตัวเองจะทำหน้าที่ไหน ไม่ต้องจำ URL ของแต่ละไฟล์แยกกัน

## ห้องคาราโอเกะสำรอง

ในหน้าเลือกโหมดการแสดงผลเดียวกัน (ด้านล่างตัวเลือกจอหลัก/จอที่ 2/รีโมท) มีกริดไอคอนลิงก์ด่วนไปยังเว็บคาราโอเกะอื่นๆ ให้เลือกใช้เผื่อกรณีฉุกเฉิน (เช่น เว็บนี้มีปัญหาชั่วคราว) — กดไอคอนแล้วเปิดเว็บนั้นในแท็บใหม่ทันที ไม่กระทบเซสชันของ Sri Karaoke ที่เปิดอยู่เดิม

⚠️ **สิ่งที่ควรทราบ**: เว็บเหล่านี้เป็น**เว็บของผู้ให้บริการภายนอก ไม่มีความเกี่ยวข้องหรือรับผิดชอบใดๆ กับโปรเจกต์นี้** เพิ่มไว้ตามที่ผู้ดูแลระบบระบุมาเองเพื่อความสะดวกเท่านั้น หากต้องการแก้ไข/เพิ่ม/ลบรายการ แก้ไขได้ที่ไฟล์ `index.html` ในส่วน `<div class="backup-rooms-grid">` แต่ละรายการเป็นแท็ก `<a>` มาตรฐาน (ชื่อ, ไอคอน, ลิงก์ปลายทาง) แก้ตรงๆ ได้เลยโดยไม่กระทบส่วนอื่น

## Screensaver ตอนไม่มีเพลงเล่น

เมื่อคิวว่างหรือยังไม่มีเพลงเล่น (จอหลัก) แทนที่จะเป็นพื้นหลังนิ่งๆ ตอนนี้จะมีบรรยากาศห้องคาราโอเกะให้ดูระหว่างรอ:
- **สปอตไลท์เวที 3 ดวง** สีขาว/ชมพู/ฟ้า ส่ายกวาดไปมาจากด้านบนของจอ แต่ละดวงมีจังหวะและมุมส่ายไม่เท่ากัน ให้ดูเป็นธรรมชาติ
- **แสงวาบสั้นๆ** เป็นระยะเมื่อสปอตไลท์ส่ายมาทางกล้อง/คนดู (ทุกๆ ~6.5 วินาที ตั้งใจให้ห่างและเบาพอที่จะไม่รบกวนสายตาหรือเสี่ยงกับคนที่ไวต่อแสงกระพริบ)
- **จุดแสงสีคมชัด 4 สี** (ชมพู/ทอง/ฟ้า/ม่วง) ลอยเคลื่อนไหวช้าๆ ใช้ไล่โทนสีแบบ radial-gradient แทนการเบลอทั้งดวง ทำให้แสงดูมีขอบชัดเจนและสดใสกว่าเดิม
- **ไฟกระพริบเล็กๆ 12 จุด** รอบขอบจอ คล้ายไฟประดับ/ไฟดวงเล็กในห้องคาราโอเกะ กระพริบไม่พร้อมกันให้ดูมีชีวิตชีวา
- โลโก้ Sri Karaoke ลอยเคลื่อนที่วนไปรอบจอแบบสุ่มทิศทาง (คล้าย DVD screensaver)
- ปุ่ม "เริ่มระบบ" และข้อความต้อนรับอยู่ในกล่องโปร่งแสงตรงกลางจอ อ่านง่ายแม้พื้นหลังเคลื่อนไหว
- ถ้าเบราว์เซอร์/อุปกรณ์ของผู้ใช้ตั้งค่า "ลดการเคลื่อนไหว" (`prefers-reduced-motion`) ไว้ ระบบจะปิดอนิเมชันและแสงวาบทั้งหมดให้อัตโนมัติ เพื่อความปลอดภัยของคนที่ไวต่อแสงกระพริบ

เอฟเฟกต์ทั้งหมดเป็น CSS animation ล้วน ไม่กินทรัพยากรเครื่องมาก ปรับสี/ความเร็ว/มุมส่ายได้ที่ `.spotlight`, `.disco-dot`, `.led`, `#screensaver-logo` และ `@keyframes` ที่เกี่ยวข้องในไฟล์ `index.html`

## เสียงเพลง "กรุณาเลือกเพลง" ตอนคิวว่าง

เมื่อคิวเพลงว่าง (ทั้งตอนเข้าระบบครั้งแรกที่ยังไม่มีใครเพิ่มเพลง และตอนเพลงสุดท้ายในคิวเล่นจบ) ระบบจะเล่นไฟล์เสียง `assets/please-select-song.mp3` วนซ้ำไปเรื่อยๆ จนกว่าจะมีเพลงถูกเพิ่มเข้าคิว แล้วหยุดทันทีที่เริ่มเล่นเพลงจริง

- ต้องกดปุ่ม "เริ่มระบบ" ก่อน 1 ครั้งเหมือนเสียงอื่นๆ ในแอป (ข้อจำกัดของเบราว์เซอร์ ไม่ใช่ของแอป)
- เล่นเฉพาะที่จอซึ่งเป็นแหล่งเสียงหลักอยู่ตอนนั้น (ดูหัวข้อ "เลือกได้ว่าจะให้ออกจากจอไหน" ด้านบน) และใช้ระดับเสียง/การปิดเสียงเดียวกับที่ตั้งไว้ในแอป
- **เปลี่ยนไฟล์เสียงเองได้**: แทนที่ไฟล์ `assets/please-select-song.mp3` ด้วยไฟล์ mp3 อื่นที่ตั้งชื่อเดียวกัน หรือแก้ path ใน `index.html` ที่ `<audio id="idle-jingle" src="...">` ให้ชี้ไปไฟล์ใหม่

## บรรยากาศ/ความสนุกสด

- **คอนเฟตติ้ฉลองคะแนนสูง** — ร่วงลงมาอัตโนมัติเมื่อได้คะแนนร้องเพลง 90 ขึ้นไป แสดงทั้งจอหลักและจอที่ 2
- **ปุ่มส่งอิโมจิ 😀** — อยู่ที่เมนู header ของจอหลัก (เปิดแผงกลางจอ มีอิโมจิให้เลือก 26 แบบ: 👍🔥❤️👏🎉💯🍻💞🤘🫶😍😮😁😂😜🤫🥱🤭🎊🫰💤🌹🎂🎄🪼🐧) และมุมบนขวาของรีโมท (ข้างปุ่ม 🔊 เอฟเฟกต์เสียง — เปิดเป็นแถบเลื่อนเลือกอิโมจิ) กดอิโมจิไหนก็ลอยขึ้นแสดงที่จอหลักและจอที่ 2 พร้อมกัน
- **โหวตเพลงถัดไป** — ที่แท็บ "คิวเพลง" บนรีโมท มีปุ่ม 🗳️ ข้างเพลงแต่ละเพลงในคิว (ยกเว้นเพลงที่กำลังเล่นอยู่) กดเพื่อโหวตว่าอยากฟังเพลงไหนต่อ เปลี่ยนใจกดเพลงอื่นได้ตลอด (นับแค่โหวตล่าสุด) ตัวเลขโหวตจะขึ้นเป็นป้ายกำกับที่ชื่อเพลงให้ทั้งจอหลักและรีโมททุกเครื่องเห็นพร้อมกัน — **เป็นเพียงข้อมูลแนะนำเท่านั้น ไม่ได้เปลี่ยนลำดับคิวให้อัตโนมัติ** แอดมินยังคงเป็นคนตัดสินใจเลือกเพลงเองเหมือนเดิม โหวตจะถูกล้างอัตโนมัติทุกครั้งที่เปลี่ยนเพลง
- **หน้าจอ "สรุปค่ำคืนนี้"** — ขึ้นอัตโนมัติทุกครั้งที่กดปุ่ม "เริ่มงานใหม่" (ก่อนที่ข้อมูลจะถูกล้างจริง) สรุป: จำนวนเพลงที่เล่นทั้งหมด, นักร้องยอดเยี่ยม (คะแนนเฉลี่ยสูงสุด), เพลงฮิตที่สุด (เล่นซ้ำบ่อยสุด), ผู้ร้องมากที่สุด, และคะแนนสูงสุดของคืนนั้น — กด "ปิด แล้วเริ่มงานใหม่" เพื่อดำเนินการล้างข้อมูลต่อตามปกติ

## ภาพพื้นหลังตอนคิวว่าง (ในหน้าตั้งค่า)

ตั้งค่า → "ภาพพื้นหลังตอนคิวว่าง" เพิ่มภาพของตัวเองให้แสดงแทนหน้าจอดิสโก้ตอนไม่มีเพลงเล่นอยู่ (คิวว่าง หรือเล่นจบแล้วไม่มีเพลงถัดไป)

- **เพิ่มภาพ** — เลือกได้หลายภาพพร้อมกัน สูงสุด 20 ภาพ ระบบย่อภาพให้ไม่เกิน 1920px อัตโนมัติเพื่อประหยัดหน่วยความจำ
- **จำไว้ถาวร** — ภาพถูกเก็บในเบราว์เซอร์ (IndexedDB) เลือกครั้งเดียวใช้ได้ตลอด ไม่ต้องเลือกใหม่ทุกครั้งที่รีเฟรชเหมือนโฟลเดอร์เพลง
- **สไลด์โชว์** — ถ้ามีมากกว่า 1 ภาพ จะเปลี่ยนภาพวนไปเรื่อยๆ แบบเฟดนุ่มๆ ตั้งเวลาได้ 5 วินาที / 10 / 15 / 30 / 1 นาที / 2 นาที / 5 นาที (ค่าเริ่มต้น 10 วินาที) และเลือกได้ว่าจะเรียงตามลำดับหรือสุ่ม (โหมดสุ่มจะไม่แสดงภาพเดิมซ้ำติดกัน)
- **ถ้าไม่เพิ่มภาพเลย** — ใช้หน้าจอดิสโก้เดิมเหมือนทุกประการ ลบภาพทั้งหมดเมื่อไหร่ก็กลับมาเป็นหน้าจอเดิมทันที
- เมื่อมีภาพพื้นหลัง แสงสปอตไลท์/ดิสโก้/ไอคอนธีมเทศกาลจะถูกซ่อน (กันแย่งความสนใจจากภาพ) แต่ยังคงโลโก้และข้อความ "ไม่มีเพลงในคิว" ไว้ พร้อมแถบมืดจางๆ ให้อ่านออกบนภาพทุกแบบ
- ลบทีละภาพได้ด้วยปุ่ม ✕ บนภาพย่อ
- **แสดงที่จอที่ 2 ด้วย** — ถ้าเปิดใช้งานจอที่ 2 อยู่ ภาพจะถูกส่งไปให้อัตโนมัติ ไม่ต้องตั้งค่าอะไรเพิ่ม และจอที่ 2 ใช้เวลา/ลำดับเดียวกับที่ตั้งไว้ที่จอหลัก (เพิ่ม/ลบภาพที่จอหลักแล้วจอที่ 2 อัปเดตตามเอง) จอที่ 2 แสดงภาพเฉพาะตอนไม่มีเพลงในคิว ส่วนตอนเล่นเพลงไฟล์ในเครื่อง (ที่ขึ้นข้อความ "กำลังเล่นจากอุปกรณ์ที่จอหลัก") จะคงหน้าจอเดิมไว้

**ข้อควรทราบ:**
- ภาพต้นฉบับเก็บในเครื่องจอหลักเท่านั้น และไม่รวมในไฟล์สำรองข้อมูล (.json) เพราะจะทำให้ไฟล์ใหญ่มาก
- **การส่งไปจอที่ 2:** ส่งผ่านการเชื่อมต่อเดิมทีละภาพ (ภาพละประมาณ 100-600 KB) จอที่ 2 จะเริ่มแสดงภาพแรกที่มาถึงก่อน ที่เหลือทยอยตามมา — ถ้าเพิ่งเพิ่มภาพจำนวนมากและ WiFi ช้า อาจใช้เวลาสักครู่กว่าจะครบ ระหว่างนั้นการสั่งงานปกติ (ข้ามเพลง ฯลฯ) ไม่ถูกขัดขวาง เพราะระบบรอให้ภาพหนึ่งส่งเสร็จก่อนค่อยส่งภาพถัดไป
- จอที่ 2 เก็บภาพไว้ในหน่วยความจำเท่านั้น (ไม่เก็บถาวร) — ถ้าต่อสัญญาณใหม่ชั่วคราวจะไม่โหลดซ้ำ แต่ถ้ารีเฟรช/ปิดเปิดหน้าจอที่ 2 จะโหลดภาพจากจอหลักใหม่อีกครั้ง
- จอหลักกับจอที่ 2 ต่างฝ่ายต่างเปลี่ยนภาพตามเวลาของตัวเอง จึงอาจไม่ได้แสดงภาพเดียวกันในจังหวะเดียวกัน (โดยเฉพาะโหมดสุ่ม)
- ปุ่ม "เริ่มงานใหม่" **ไม่ลบ**ภาพพื้นหลัง เพราะเป็นการตั้งค่าของระบบ ไม่ใช่ข้อมูลของงานนั้น
- ภาพจะหายถ้าล้างข้อมูลเว็บไซต์ (Clear site data) ของเบราว์เซอร์
- ถ้าเบราว์เซอร์ไม่อนุญาตให้เก็บข้อมูลถาวร (เช่นบางโหมดไม่ระบุตัวตน) ภาพจะใช้ได้จนกว่าจะรีเฟรชหน้า — ระบบจะแจ้งเตือนในหน้าตั้งค่า

## กล้องสดเป็นพื้นหลัง (จอหลัก + จอที่ 2)

ใช้กล้องของอุปกรณ์จอหลัก (กล้องในเครื่อง หรือเว็บแคมที่เสียบ USB) ถ่ายทอดสดเป็นพื้นหลังแทนภาพสไลด์โชว์ ตั้งที่ **⚙️ ตั้งค่า → "ภาพพื้นหลังตอนคิวว่าง" → "แหล่งพื้นหลัง"** เลือก **📷 กล้องสด** (เลือกได้อย่างใดอย่างหนึ่ง: ภาพนิ่ง/สไลด์โชว์ หรือ กล้องสด) แล้วเบราว์เซอร์จะขออนุญาตใช้กล้อง — กด **อนุญาต**

**แสดงที่ไหน** (ทั้งจอหลักและจอที่ 2 แสดงเหมือนกัน):
| ตอนไหน | แสดงอย่างไร |
|---|---|
| คิวว่าง (ไม่มีเพลง) | เต็มจอแทนหน้าจอดิสโก้ |
| เล่นไฟล์ MP3 | เป็นพื้นหลังเต็มจอหลังเนื้อเพลง (มีแถบมืดจางๆ ให้เนื้อเพลงอ่านออก) |
| เล่นวิดีโอ (YouTube / ไฟล์วิดีโอ) | หน้าต่างเล็กมุมบนซ้าย ชิดใต้ header (หรือชิดขอบบนถ้าซ่อน header) และหลบแผงเสียงเอฟเฟกต์เมื่อเปิดอยู่ — **แถบคอร์ด แถบ "ถัดไป" และแผงอิโมจิจะทับอยู่เหนือหน้าต่างนี้ได้** (ใช้ไม่บ่อยและไม่ได้เปิดค้าง) แตะทะลุหน้าต่างไปที่วิดีโอได้ตามปกติ |

**สวิตช์ที่ตั้งได้** (จดจำไว้ที่เครื่อง): 📷 เลือกกล้อง (ถ้ามีหลายตัว) · 🖥️ แสดงที่จอหลัก · 📺 ส่งไปแสดงที่จอที่ 2 (**เปิด/ปิดแยกจากจอหลักได้** เช่น แสดงเฉพาะจอที่ 2 ก็ได้) · 🎚️ คุณภาพภาพที่ส่งไปจอที่ 2 (สูง 720p / **กลาง 540p — ค่าเริ่มต้น** / ต่ำ 360p) · 🪟 หน้าต่างเล็กตอนเล่นวิดีโอ · 🔁 กลับด้านซ้าย-ขวา (เหมือนส่องกระจก)

**ถ้ากล้องใช้ไม่ได้** (ไม่อนุญาต, ถอดสาย, ไม่พบกล้อง, มีโปรแกรมอื่นใช้อยู่, หรือเบราว์เซอร์ไม่รองรับ) ทุกหน้าจอ **กลับไปแสดงพื้นหลังเดิมให้อัตโนมัติ**: ภาพสไลด์โชว์ที่ตั้งไว้ หรือไฟดิสโก้ถ้าไม่ได้ตั้งภาพไว้ — พร้อมแจ้งสาเหตุในหน้าตั้งค่า (สถานะสีแดง) และข้อความแจ้งเตือนหนึ่งครั้ง (ไม่เด้งซ้ำ):
- **เสียบกล้องกลับ → กลับมาเอง** (ระบบจับการเสียบ/ถอดอุปกรณ์ และตอนที่กลับมาเปิดแท็บ) หรือกด **"เปิดกล้อง / ลองเชื่อมต่ออีกครั้ง"**
- **ถูกปฏิเสธการอนุญาต:** ระบบไม่ถามซ้ำเอง (ไม่รบกวน) — กดไอคอนกล้อง/แม่กุญแจที่แถบที่อยู่ของเบราว์เซอร์ เลือก "อนุญาต" แล้วกดปุ่มลองอีกครั้ง

**กล้องเริ่มทำงานหลังจากกดเลือก "จอหลัก" ที่หน้าต้อนรับเท่านั้น** (ไม่เปิดตอนยังอยู่หน้าข้อมูลเว็บไซต์/เลือกบทบาท — กันไม่ให้ขึ้นหน้าต่างขออนุญาตหรือไฟกล้องติดบนอุปกรณ์ที่กำลังจะถูกใช้เป็นรีโมทหรือจอที่ 2)

**กล้องเปิดเฉพาะตอนที่มีหน้าจอต้องแสดงภาพ:** ถ้าไม่มีหน้าจอไหนต้องใช้ (เช่นปิดหน้าต่างเล็กไว้แล้วกำลังเล่นวิดีโอ) กล้องจะปิดเองหลังผ่านไปประมาณ 5 วินาที (ไฟกล้องดับ) และเปิดใหม่อัตโนมัติเมื่อต้องใช้ ระหว่างเปลี่ยนเพลงไม่กะพริบเปิด-ปิด

**ข้อควรรู้:**
- **ต้องเปิดเว็บผ่าน HTTPS** (เหมือนที่รีโมทต้องใช้) เบราว์เซอร์ถึงจะยอมให้ใช้กล้อง
- วางเป็นพื้นหลัง "หลัง" วิดีโอ YouTube ไม่ได้ (วิดีโอเป็นกรอบทึบเต็มจอ) จึงใช้หน้าต่างเล็กมุมจอแทน
- ส่งภาพสดไปจอที่ 2 ผ่านเครือข่าย (WebRTC เข้ารหัส ไม่ผ่านเซิร์ฟเวอร์ของแอป) ภาพจะช้ากว่าต้นทางเล็กน้อย และเครื่องจอหลักที่สเปกไม่แรงอาจหน่วงลง — ปิดสวิตช์ "ส่งไปจอที่ 2" หรือปิดหน้าต่างเล็กได้ และลด **"คุณภาพภาพที่ส่งไปจอที่ 2"** ได้ (กลาง 540p/24fps เป็นค่าเริ่มต้น ลดภาระการเข้ารหัสราวครึ่งหนึ่งเทียบกับ 720p/30fps; ภาพที่จอหลักยังคมเท่าเดิมเสมอ เปลี่ยนแล้วมีผลทันทีโดยไม่ต้องต่อใหม่)

**ภาพที่จอที่ 2 หน่วง/กระตุก — ดูตัวเลขจริงได้ในตั้งค่า:** ขณะกำลังส่งภาพไปจอที่ 2 ที่ ตั้งค่า → ภาพพื้นหลัง → กล้องสด จะมีข้อความสถานะที่อัปเดตทุก 3 วินาที แสดงว่าเวลาหายไปที่ไหน: ขนาด/เฟรมเรตที่ส่ง, เวลาเข้ารหัสต่อเฟรม (ฝั่งจอหลัก), บัฟเฟอร์/เวลาถอดรหัส/เฟรมที่ทิ้ง/RTT (ฝั่งจอที่ 2), ต่อตรงหรือผ่านเซิร์ฟเวอร์ relay และ **ความหน่วงโดยประมาณ** ในวง WiFi เดียวกันปกติราว **150-400 มิลลิวินาที** ถ้าสูงกว่า ~800 มิลลิวินาทีจะขึ้นเตือน "สูงกว่าปกติ" พร้อมสาเหตุที่น่าจะเป็น:
- **ผ่าน relay** → สองเครื่องไม่ได้อยู่วง WiFi เดียวกัน/เครือข่ายบล็อกการต่อตรง (สาเหตุที่พบบ่อยของภาพหน่วงเป็นวินาที)
- **เข้ารหัสไม่ทัน (CPU)** หรือเวลาเข้ารหัสต่อเฟรมสูง → จอหลักแรงไม่พอ ลดคุณภาพภาพที่ส่ง
- **บัฟเฟอร์สูง / แพ็กเก็ตหาย** → WiFi ของจอที่ 2 ไม่นิ่ง
- **ถอดรหัสไม่ทัน** → เครื่องจอที่ 2 แรงไม่พอ ลดคุณภาพภาพที่ส่ง

หมายเหตุ: ตัวเลขนี้วัดเฉพาะเส้นทางส่งภาพ (เข้ารหัส→เครือข่าย→บัฟเฟอร์→ถอดรหัส) ไม่รวมความหน่วงของตัวกล้องเองและการแสดงผลของจอ จึงอาจต่ำกว่าที่ตาเห็นเล็กน้อย
- ไม่บันทึกภาพ ไม่อัปโหลดที่ไหน และ **ไม่ใช้ไมโครโฟน** (ขอเฉพาะภาพ)
- กล้อง IP / CCTV (RTSP) เปิดโดยตรงไม่ได้ ต้องแปลงสัญญาณเป็นแบบที่เบราว์เซอร์อ่านได้ก่อน; บนกล่อง/ทีวีแอนดรอยด์บางรุ่นอาจไม่มีกล้องหรือเบราว์เซอร์มองไม่เห็นเว็บแคม USB (ระบบจะแจ้งและใช้พื้นหลังเดิม)
- ขอบเขตของแขกที่อยู่หน้ากล้อง: ภาพขึ้นจอให้ทุกคนเห็นอยู่แล้ว แต่ควรแจ้งแขกด้วยว่ากำลังเปิดกล้อง และปิดได้ทุกเมื่อโดยเปลี่ยน "แหล่งพื้นหลัง" กลับเป็นภาพนิ่ง

## ธีมสี (ในหน้าตั้งค่า)

เลือกธีมสีได้ที่หน้าตั้งค่า → "ธีม" มีให้เลือก 5 แบบ: 🌙 มืด (ค่าเริ่มต้น), ☀️ สว่าง, 🎂 วันเกิด, 🎆 ปีใหม่, 💦 สงกรานต์ — ธีมเทศกาล (วันเกิด/ปีใหม่/สงกรานต์) จะมีไอคอนลอยขึ้นมาประดับที่หน้าจอว่าง (idle screen) ด้วย เช่น ลูกโป่ง/ดอกไม้ไฟ/หยดน้ำ ตามธีมที่เลือก จอวิดีโอขณะเล่นเพลงยังคงมืดเหมือนเดิมเสมอไม่ว่าจะเลือกธีมไหน (เปลี่ยนแค่สีของเมนู/หน้าต่างต่างๆ)

**ข้อมูลเทคนิค:** ธีมจำไว้ที่เครื่อง (localStorage) ไม่ใช่แค่ในเซสชันนั้น — เปลี่ยนทีเดียวใช้ได้ยาวจนกว่าจะเปลี่ยนเอง

## เสียงเอฟเฟกต์ (จอหลัก + รีโมท)

**จอหลัก**: กดปุ่มวงกลมลอยที่ขอบซ้ายของจอวิดีโอ (**▶** = แผงซ่อนอยู่ กดเพื่อเปิด · **◀** = แผงเปิดอยู่ กดเพื่อซ่อน) เพื่อเปิด/ปิดแผงเสียงเอฟเฟกต์ — ปุ่มนี้กับปุ่มซ่อน/แสดงคิวทางขวา **เป็นปุ่มวงกลมขนาดเท่ากัน** (40 พิกเซล ปรับพร้อมกันได้ที่ตัวแปร `--tog-size` ใน `index.html`) ตำแหน่งของแต่ละปุ่มไม่เปลี่ยน — แสดงเป็นแถบแนวตั้งทับด้านซ้ายของวิดีโอ พื้นหลังโปร่งใส 28% ไม่บังวิดีโอทั้งหมด ปุ่มแต่ละปุ่มมี**ขนาดเท่ากันทุกปุ่ม** ชื่อยาวเกินจะถูกตัดด้วย "..." อัตโนมัติ (ชี้เมาส์ค้างที่ปุ่มเพื่อดูชื่อเต็ม)

**รีโมท (ทั้งผู้ใช้ทั่วไปและแอดมิน)**: กดไอคอน 🔊 ที่มุมขวาบนของหน้าจอ (ข้างรหัสห้อง) เพื่อเปิด/ปิดแถบเอฟเฟกต์แนวนอนด้านบน (ปุ่มขนาดเท่ากันทุกปุ่มเช่นกัน) — กดปุ่มเอฟเฟกต์จากรีโมทแล้วเสียงจะไปเล่นที่จอหลัก (หรือจอที่ 2 ถ้าตั้งค่าเสียงออกจอ 2 ไว้) เพราะรีโมทเองไม่มีลำโพงที่เชื่อมกับระบบเสียงหลัก

### วิธีเพิ่มไฟล์เสียงเอฟเฟกต์เอง
เว็บนี้เป็น Static Site (ไม่มีเซิร์ฟเวอร์ประมวลผล) จึงไม่สามารถสแกนโฟลเดอร์หาไฟล์อัตโนมัติได้ ต้องระบุรายชื่อไฟล์เองในไฟล์ `manifest.json` ที่โฟลเดอร์ `sound-effects/` รองรับ 2 รูปแบบ:

**แบบง่าย** (ใช้ชื่อไฟล์เป็นชื่อปุ่มตรงๆ ไม่มีไอคอน):
```json
["เพลงเชียร์.mp3", "เสียงกลอง.wav"]
```

**แบบระบุไอคอน+ชื่อปุ่มเอง** (แนะนำ — ใช้แบบนี้อยู่แล้วกับ 10 เสียงที่มีมาให้):
```json
[
  { "file": "เพลงเชียร์.mp3", "icon": "📣", "label": "เชียร์สุดใจ" }
]
```
ผสมทั้งสองแบบในไฟล์เดียวกันได้ตามสะดวก

**ขั้นตอน:**
1. อัปโหลดไฟล์เสียง (.mp3 .wav .ogg .m4a .aac) ไปไว้ในโฟลเดอร์ `sound-effects/`
2. เปิดไฟล์ `sound-effects/manifest.json` แล้วเพิ่มรายการใหม่ (แบบใดแบบหนึ่งข้างบน) — อย่าลืมคอมมาคั่นระหว่างรายการ
3. บันทึกไฟล์ แล้วรีเฟรชหน้าจอหลัก — ปุ่มใหม่จะขึ้นให้อัตโนมัติ
4. จำนวนปุ่มที่แสดงจะเท่ากับจำนวนรายการที่ระบุไว้ใน manifest.json (ไม่ใช่จำนวนไฟล์จริงในโฟลเดอร์ ถ้าลืมเพิ่มในลิสต์ ปุ่มจะไม่ขึ้นแม้ไฟล์จะอยู่ในโฟลเดอร์แล้วก็ตาม)

มีคำแนะนำแบบเดียวกันนี้อยู่ในไฟล์ `sound-effects/README.txt` ด้วย ต้องรีเฟรชหน้าจอหลักหลังแก้ manifest.json ทุกครั้งที่เพิ่ม/ลบรายการ (ระบบจะส่งรายชื่อใหม่ไปให้รีโมท/จอที่ 2 ที่เชื่อมต่ออยู่โดยอัตโนมัติหลังจากนั้น ไม่ต้องรีเฟรชฝั่งรีโมทเอง)

## ปรับปรุงความปลอดภัย

ปิดช่องโหว่การแทรกโค้ด (XSS) ที่พบระหว่างตรวจสอบโค้ด — ฟิลด์ "ภาพปกเพลง" (thumbnail) ที่ส่งมาจากรีโมทตอนเพิ่มเพลงเข้าคิว ไม่เคยผ่านการป้องกันอักขระพิเศษก่อนแสดงผล ทำให้ในทางทฤษฎีมีความเสี่ยงที่ใครก็ตามที่เชื่อมต่อเป็นรีโมทอยู่จะส่งข้อมูลปลอมแปลงเข้ามาแทรกโค้ดในเบราว์เซอร์ของจอหลักและรีโมทเครื่องอื่นๆ ที่เชื่อมต่ออยู่พร้อมกันได้ — แก้ไขโดยปรับฟังก์ชันป้องกันอักขระพิเศษ (`escapeHtml`) ให้ครอบคลุมเครื่องหมายคำพูดด้วย และนำไปใช้ครบทุกจุดที่แสดงภาพปกเพลงแล้วทั้งจอหลักและรีโมท

## ข้อจำกัดที่ควรทราบ

- ต้องเชื่อมต่ออินเทอร์เน็ตตลอดการใช้งาน (สำหรับ YouTube, PeerJS broker, และ Google Fonts)

- หากปิด/รีเฟรชหน้าจอหลัก รหัสห้องจะเปลี่ยนใหม่ทุกครั้ง ต้องสแกน QR ใหม่
